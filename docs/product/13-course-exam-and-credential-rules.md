# 13｜T034 课程考试与证书分层

> 状态：原型规则已收口  
> 日期：2026-08-24  
> 范围：移动端课程列表、课程详情、考试、课程成果与证书详情

## 1. Owner 已确认的核心原则

可信证书存在真实签发成本，因此**不是所有任务、课程、成果都适合做可信证书**。

产品必须先判断内容价值，再决定是否配置可信证书，而不是：

```text
完成一件事
→ 默认发可信证书
```

正确关系是：

```text
简单任务 / 日常行为
→ 不发可信证书

普通课程
→ 可配置普通电子证书

高价值课程
→ 高学力值兑换
→ 完成学习与考核
→ 才进入可信证书签发 / 领取
```

新手任务等简单任务不配置可信证书。

## 2. 三档成果表达

### A. 仅学习记录

适用于不需要发证的内容。

- 完成后保留学习进度 / 学习成果；
- 不出现证书入口；
- 不出现验真、可信空间、签发等强表达。

### B. 普通电子证书

适用于普通课程结业证明。

- 完成课程并通过考核后生成；
- 可以保存 / 下载；
- 不展示验真码；
- 不展示官方验真入口；
- 不使用“可信证书”文案和强视觉。

### C. 可信证书

只适用于平台认为值得承担真实签发成本的高价值课程。

App 中必须提前表现这种差异：

- 明确“可信证书”标签；
- 采用较高学力值兑换门槛；
- 通过考核后进入签发 / 领取；
- 领取后才进入可信证书详情与验真流程。

当前 T034 原型只选择 `AI 电商智能体实战` 作为可信课程示例。它沿用现有课程数据中的 250 学力值，属于当前目录最高学力值档。该数值仅用于原型比较，不视为最终定价。

## 3. 付费课程试看

学力值兑换课程必须允许用户在兑换前判断课程是否适合自己。

当前原型：

```text
课程详情
→ 试看第 1 节
→ 不扣学力值
→ 结束试看
→ 再决定是否兑换完整课程
```

真实视频资源后续接入，不影响当前入口结构。

## 4. 考试次数

考试限制必须在用户进入考试时直接展示，不能等提交失败后才告知。

会议曾举例“每月两次”。T034 原型暂采用：

> 每门课程每月 2 次考试机会

用于验证：

- 剩余次数展示；
- 未通过后的剩余次数；
- 次数耗尽状态。

**2 次 / 月目前是原型参数，不是最终业务规则。**

## 5. 当前课程示例分层

原型按现有课程数据演示：

- `AI 电商智能体实战`：可信证书 + 当前最高学力值兑换档；
- 已配置 `certificateId` 的其它课程：普通电子证书；
- 未配置 `certificateId` 的课程：仅学习记录。

该映射用于验证页面层级，不代表最终课程目录的商业配置。

## 6. 明确不做

T034 不继续设计：

- 可信证书真实成本核算；
- 最终课程定价；
- 最终及格线；
- 复杂补考 / 申诉规则；
- 证书撤销后台；
- 视频 DRM / 防录屏；
- 考试防作弊系统。

这些不是当前产品原型评审所必需。
