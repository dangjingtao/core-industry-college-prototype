# 20｜成长运营后台 MVP

> 状态：Draft / MVP 结构已确认  
> 日期：2026-08-26  
> 适用：现有 PC 管理端 `/admin/*`  
> 前置：`19-badge-ad-and-trusted-credential-prd.md`  
> 对应：T038 / T039 / T040 / T041 / T042

---

## 1. 目标

在现有 PC 管理端新增一级菜单 **「成长运营」**，用一套轻量后台承接学生侧的：

- 徽章；
- 可信课程与可信证书资格；
- 运营大礼包；
- 广告场景。

首期目标不是建设万能规则引擎，而是让运营能够独立完成日常配置，同时保持学生端、课程、广告、权益与可信证书的业务口径一致。

---

## 2. MVP 导航

```text
成长运营
├─ 徽章管理
├─ 可信证书
│  ├─ 资格规则
│  └─ 签发记录
├─ 大礼包
└─ 广告场景
```

建议路由：

```text
/admin/growth/badges
/admin/growth/certificates/rules
/admin/growth/certificates/records
/admin/growth/gifts
/admin/growth/ad-scenes
```

首期不单独做「成长运营首页 / 数据大屏」。如果需要入口概览，可在菜单顶部放 4 个简单数量卡，不为此增加独立页面。

---

## 3. 权限：MVP 先收紧

首期只允许 **平台运营 / 超级管理员** 创建、编辑和启停徽章、证书资格、大礼包与广告场景。

课程运营、赛事运营等角色可以在其业务页面产生事实，但**不直接拥有成长规则创建权限**。

原因：

- 当前规则仍处于原型验证期；
- 多角色同时配置容易造成徽章泛滥或重复规则；
- 后续若明确需要，可再增加「业务域 + 数据范围」授权，不影响当前数据模型。

---

## 4. 徽章管理

### 4.1 列表页

列表至少展示：

| 字段 | 说明 |
| --- | --- |
| 徽章 | 图形 + 名称 |
| 品相 | G1 / G2 / G3 / G4（视觉命名待定） |
| 来源 | App 行为 / 学习 / 考核 / 赛事 / 进度 / 运营 |
| 获得条件 | 人类可读摘要，例如「连续签到 7 天」 |
| 已获得人数 | 原型可用 mock 统计 |
| 状态 | 草稿 / 启用 / 停用 |
| 更新时间 | 最近规则修改时间 |

支持：

- 搜索名称；
- 按品相筛选；
- 按来源筛选；
- 按状态筛选；
- 新建；
- 编辑；
- 停用；
- 查看获得记录。

已发放徽章停用后不删除学生历史资产，只停止继续发放。

### 4.2 新建 / 编辑徽章

基础字段：

```text
名称
图形 / 图标
说明
来源类型
品相 G1-G4
获得规则模板
规则参数
生效时间（可选）
状态
```

### 4.3 MVP 规则模板

首期不提供自由 AND / OR 条件编辑器，只提供模板化规则。

#### 模板 A｜累计行为

用于：

- 累计完成 N 次激励广告；
- 累计签到 N 天；
- 累计完成某类平台行为。

配置：

```text
行为类型 + 累计次数
```

#### 模板 B｜连续行为

用于：连续签到等。

配置：

```text
行为类型 + 连续天数
```

#### 模板 C｜课程完成

配置：

```text
指定课程
```

课程完成事实来自课程学习记录；徽章系统不复制课程进度。

#### 模板 D｜考核通过

配置：

```text
指定小测 / 考核 + 通过状态
```

#### 模板 E｜赛事 / 进度事实

配置：

```text
指定赛事（可选） + 事实类型 + 目标状态
```

例如：获得参赛身份、进入某阶段、完成某项目节点。

### 4.4 MVP 暂不做

- 任意多层 AND / OR 规则；
- 徽章依赖另一枚徽章的复杂嵌套；
- 运营自行写表达式 / SQL；
- 自动 AI 生成规则；
- 徽章交易、转让、合成、分解。

如果未来出现「学力值 + App 行为」等复杂高级徽章需求，再增加组合模板，不在首期提前建设万能规则编辑器。

## 5. 可信证书｜资格规则

### 5.1 规则列表

每条规则代表一个可信课程 / 微专业对应的可信证书资格。

列表展示：

- 证书名称；
- 指定可信课程；
- 课程自带徽章；
- G3 最低数量；
- G1 最低数量；
- 结业考试；
- 签发渠道；
- 状态；
- 已签发人数。

### 5.2 新建 / 编辑资格规则

MVP 使用固定结构，不做通用资格表达式：

```text
证书名称
指定可信课程（必填）
课程完成徽章（显示该课程完成后自动获得的徽章）
G3 徽章最低数量
G1 徽章最低数量
结业考试（必填）
签发 Provider / 证书模板
状态
```

当前默认产品结构：

```text
指定可信课程完成（课程自带徽章）
+ G3 徽章 >= 2
+ G1 徽章 >= 5
+ 结业考试通过
→ 达到可信证书资格
```

数值作为规则字段保存，当前原型默认 `G3 = 2`、`G1 = 5`，后续运营可按统一产品规则调整。

**硬约束：指定可信课程不能为空。** 后台不提供「只靠徽章拿证」的配置能力。

### 5.3 资格判定

学生事实发生变化时重新判断资格：

```text
课程完成 / 徽章新增 / 结业考试通过
→ 资格规则判断
→ 未满足：继续积累
→ 已满足：生成签发任务
```

规则判断只读取课程、徽章、考试事实，不复制它们。

## 6. 可信证书｜自动签发记录

### 6.1 不做人工审批

学生满足完整资格后，系统**自动调用外部可信认证 API 签发**，不增加运营人工批准步骤。

流程：

```text
资格满足
→ 创建唯一签发任务
→ 调用外部 Provider API
→ 成功：生成可信证书资产
→ 失败：进入失败状态，按策略重试
```

### 6.2 为什么仍需要后台记录页

外部签发存在真实成本，当前业务口径约 10 元 / 份，因此即使自动签发，也必须能观察：

- 谁满足了资格；
- 哪条规则触发；
- 是否已调用 Provider；
- Provider 返回结果；
- 是否失败；
- 是否重试；
- 最终证书 ID / 验真信息。

### 6.3 签发记录列表

状态建议：

```text
待签发 pending
签发中 issuing
已签发 issued
失败 failed
```

列表字段：

- 学生；
- 证书；
- 可信课程；
- 资格达成时间；
- Provider；
- 状态；
- 尝试次数；
- 最后错误；
- 外部证书 ID；
- 签发时间。

支持：

- 状态筛选；
- 学生 / 证书搜索；
- 查看详情；
- 对失败记录执行「重试」。

不提供「人工跳过资格直接签发」。

### 6.4 成本与幂等保护

签发任务必须有稳定幂等键，例如：

```text
studentId + certificateRuleId
```

同一学生同一证书规则只能形成一份有效签发任务，防止页面刷新、重复事件或人工重试造成重复扣费 / 重复发证。

失败重试必须复用原任务，不创建第二份独立签发事实。

## 7. 大礼包

### 7.1 产品规则

学生满足礼包徽章条件后**自动解锁领取资格**，不经过人工审核。

大礼包用于承接不以可信课程 / 可信证书为目标、但持续参与平台行为的学生回馈。

### 7.2 列表页

展示：

- 礼包名称；
- 内容摘要；
- 徽章门槛；
- 活动时间；
- 总量 / 剩余量（若有限量）；
- 已解锁人数；
- 已领取人数；
- 状态。

### 7.3 新建 / 编辑

MVP 字段：

```text
礼包名称
说明 / 展示图
有效时间
G1-G4 最低数量（按需填写）
指定必备徽章（可选）
库存 / 限量（可选）
领取后承接方式
状态
```

满足条件：

```text
所有已配置的品相数量门槛
+ 所有指定必备徽章
→ 自动解锁领取资格
```

领取动作和实际权益履约继续由权益领域承接；成长运营只负责「是否有资格」。

## 8. 广告场景

平台无法控制广告平台实际竞价与素材，因此这里不做广告投放后台。

### 8.1 场景列表

首期固定出现现有业务场景：

- 福利领取激励广告（T038）；
- 权益详情信息流（T038）；
- 机会板块信息流（T039）；
- App 冷启动开屏（T040）；
- 每日打卡（T041）。

列表展示：

- 场景名称；
- 广告类型；
- 是否启用；
- 触发策略摘要；
- 简单频控；
- 最近修改时间。

### 8.2 可配置字段

MVP 只提供业务层参数：

```text
enabled
adType
triggerMode
skipPolicy
frequencyRule
businessAction
```

每日打卡场景额外提供：

```text
A 普通签到
B 广告作为签到条件
C 签到后广告作为额外奖励
```

广告主、素材、竞价、投放算法不在本系统配置。

---

## 9. 页面交互原则

成长运营后台以「列表 + 新建 / 编辑抽屉或详情页」为主，首期不需要复杂可视化编排器。

推荐统一交互：

```text
列表
→ 新建 / 编辑
→ 表单配置
→ 右侧实时显示“规则摘要”
→ 保存为草稿 / 启用
```

例如证书规则右侧直接显示：

> 完成《数字营销微专业》 + G3 ≥ 2 + G1 ≥ 5 + 结业考试通过 → 自动申请可信证书

让运营看到的是业务语言，而不是字段名或表达式。

## 10. 原型必须覆盖的状态

### 徽章

- 草稿；
- 启用；
- 停用；
- 已获得历史不丢失。

### 证书

- 资格未满足；
- 资格满足；
- 待签发；
- 签发中；
- 已签发；
- 签发失败；
- 失败重试。

### 礼包

- 未达门槛；
- 已解锁；
- 已领取；
- 已领完 / 已结束。

### 广告

- 场景启用 / 停用；
- no-fill 不阻塞业务；
- T041 A / B / C 三种策略至少可以在原型数据层切换。

---

## 11. MVP 不做

- 万能规则引擎；
- 任意条件树编辑器；
- 学校 / 企业自行创建成长规则；
- 人工证书审批流；
- 证书现金购买；
- 广告素材 / 广告主 / 竞价管理；
- 复杂礼包商城；
- 徽章交易 / 合成系统；
- 独立成长运营 BI 大屏。

---

## 12. 原型验收

后台原型至少可以完整演示以下两条链路：

### 链路 A｜可信证书

```text
运营创建 / 启用课程完成徽章
→ 配置可信证书规则：指定课程 + G3≥2 + G1≥5 + 结业考试
→ 学生侧满足条件
→ 后台出现自动签发记录
→ 模拟 Provider API 成功
→ 学生获得可信证书
```

并能模拟一次 API 失败 → 后台显示失败原因 → 重试成功。

### 链路 B｜运营补偿

```text
运营创建行为徽章
→ 配置大礼包徽章门槛
→ 学生通过签到 / 广告 / 活动积累徽章
→ 满足条件自动解锁礼包
→ 学生领取
```

这两条链路跑通即可认为成长运营后台 MVP 成立。
