# 19｜徽章、广告与可信证书运营机制 PRD

> 状态：Draft / 核心规则已确认，品相命名与数值待后续收口  
> 日期：2026-08-26  
> 适用：学生 App + 现有 PC 运营管理端的轻量配置能力  
> 对应任务：T038 / T039 / T040 / T041 / T042  
> 关联产品文档：`13-course-exam-and-credential-rules.md`、`14-exchange-center-and-phone-bound-benefits.md`

---

## 1. 背景与目标

平台希望建立一套长期存在的「学生行为与成长成就」机制，用于承接：

- App 日常行为；
- 课程学习与小测；
- 赛事身份、赛事进度与成果；
- 运营活动；
- 激励广告带来的行为回馈；
- 微专业课程与可信证书；
- 不以学习/拿证为目标的学生福利激励。

徽章不是单纯展示型荣誉墙。它首先是长期成就资产，同时可以作为：

1. 可信证书的资格条件之一；
2. 运营大礼包 / 大额优惠 / 礼券的领取门槛；
3. 新手任务和日常任务的目标反馈；
4. 学生长期账号中的成就记录。

本 PRD 的目标不是建设复杂游戏系统，而是先把 T038–T042 的产品关系收拢，避免广告、签到、徽章、课程和可信证书各自施工后形成相互矛盾的业务规则。

## 2. 已确认的核心原则

### 2.1 可信证书始终由可信课程兜底

平台已有外部权威可信认证签发渠道，单份签发存在真实成本，当前业务口径约为 **10 元 / 份**。可信证书未来可以进入学生简历，因此不能被设计成普通积分商品或付费商品。

可信证书的硬边界：

- 只面向平台选定的高价值 / 可信课程或微专业培养方案；
- 学生必须完成对应可信课程；
- 可以额外要求完成规定数量 / 组合的徽章；
- 可以要求关卡小测与结业考核；
- **禁止通过现金直接购买、跳过学习或跳过徽章条件获得可信证书**；
- 无论积累多少徽章，都不能绕过可信课程直接获得可信证书。

正式对外展示时，证书签发主体、认证名称和资质描述必须按真实合作关系表达，不在产品文案中夸大为未经确认的官方背书。

### 2.2 徽章本身不分“可信 / 不可信”

徽章是成就与行为记录，不等同于可信证书。

徽章可以来自：

- App 行为；
- 日常任务；
- 课程；
- 小测；
- 赛事身份；
- 赛事 / 项目进度；
- 运营活动；
- 其它未来可验证事实。

徽章的高低只描述 **获取难度、投入程度与稀缺程度**，不描述官方可信等级，也不直接等同于学生能力等级。

### 2.3 低品相徽章可以成为可信证书必选条件

可信证书可以采用类似以下组合规则：

```text
可信课程完成
+ X 个高品相徽章
+ Y 个低品相徽章
+ 必要的小测 / 结业考核
= 满足可信证书领取资格
```

其中：

- 可信课程负责学习事实与核心能力要求；
- 高 / 低品相徽章负责培养过程中的参与、投入和阶段性成就要求；
- 低品相行为徽章可以作为培养方案完成度的一部分，但不能在产品表达中被解释为专业能力证明。

### 2.4 广告是行为交换，不是“买证书”

激励广告的产品含义是：

> 学生完成平台希望发生的行为，平台获得广告收益，并将其中一部分价值通过徽章、权益或其它奖励回馈给学生。

因此允许：

```text
完成激励广告行为
→ 达成某枚行为徽章 / 某项任务条件
→ 徽章进一步参与礼包或培养方案资格判断
```

但禁止前台形成以下直接心智：

```text
看广告 → 买证书
看广告 → 直接解锁可信认证
```

可信课程始终是可信证书不可绕过的硬门槛。

### 2.5 每日打卡与广告采用可配置关系

每日打卡是独立的用户行为，不再与新手任务状态绑定。

广告与打卡不固定为单一关系，首期基座允许三种场景策略：

```text
A. 普通签到，不要求广告
B. 签到必须完成激励广告
C. 先完成签到，观看广告可获得额外奖励
```

具体采用哪一种由运营场景配置决定，不在客户端代码中永久写死。

### 2.6 徽章为长期资产

徽章一旦合法获得，应保留在学生长期账号中。

课程下架、赛事结束、活动结束后：

- 已获得徽章继续保留；
- 已结束来源停止继续发放；
- 历史徽章可继续展示其来源与获得时间；
- 不因为活动结束自动删除学生已获得成就。

## 3. 徽章模型

### 3.1 两个维度必须拆开

首期徽章至少拆成两个独立维度：

```text
徽章
├─ 来源类型（为什么获得）
│  ├─ App 行为
│  ├─ 学习 / 课程
│  ├─ 小测 / 考核
│  ├─ 赛事身份 / 赛事成果
│  ├─ 进度
│  └─ 运营活动
│
└─ 品相（获得有多难）
   ├─ G1
   ├─ G2
   ├─ G3
   └─ G4 ...
```

当前先使用 G1 / G2 / G3 / G4 作为内部占位，不在本 PRD 决定最终视觉命名。

未来可以再评审：绿 / 蓝 / 紫 / 金、C / B / A / S 或其它体系，但命名不能改变“品相只表示获取难度”的业务定义。

### 3.2 高品相徽章不强制绑定课程

完成可信课程并获得高品相学习徽章，是最理想、最稳定的一条路径，但不是唯一来源。

只要规则透明、事实可验证、投入门槛足够，高品相徽章未来也可以来自：

- 高难度赛事成果；
- 长周期项目进度；
- 学力值 + 明确 App 行为的组合；
- 其它平台认可的高投入成就。

**高品相 ≠ 自动成为简历能力证明。** 是否进入简历或可信空间，需要根据徽章来源与产品展示规则决定。

### 3.3 新手任务

新手引导可以将“获得第一枚高品相徽章”作为一个重要目标，用于让学生尽早理解平台的长期成就体系。

但不要求所有新用户在 onboarding 内强制完成一门高难课程；新手任务只负责引导到真实可达成的第一枚高品相徽章路径。

## 4. 微专业与可信证书

### 4.1 课程事实源

原则上，学校 / 合作方的微专业课程托管于 App，学习进度、课程完成、小测与结业考核以平台课程事实为依据。

徽章与证书不得复制一份独立课程完成状态。

### 4.2 统一规则

可信证书采用平台统一规则，不允许每所学校 / 企业各自建设一套不同的证书资格算法。

统一结构：

```text
指定可信课程完成
+ 指定徽章组合（可同时包含低品相与高品相）
+ 规定的小测 / 结业考核
→ 证书资格达成
→ 进入真实可信证书签发 / 领取流程
```

运营可以在统一结构内配置：

- 哪些课程属于可信课程；
- 哪些徽章计入资格；
- X / Y 数量或指定组合；
- 关卡小测 / 结业考试规则；
- 证书展示信息。

但不能配置“无需可信课程即可拿证”的例外。

### 4.3 简历关系

可信证书领取成功后：

- 进入学生长期可信资产；
- 可进入可信空间；
- 学生可以在简历中选择展示；
- 简历展示引用证书真实事实，不复制或手填一份“可信证书”。

普通徽章是否进入简历，后续按徽章来源分别设计，不默认所有行为徽章都作为能力证据进入简历。

## 5. 徽章的第二条价值出口：运营大礼包

并非所有学生都愿意通过 App 学习可信课程、最终获得可信证书。

因此徽章必须有独立于“拿证”的第二条价值出口：

```text
获得徽章
→ 满足运营礼包门槛
→ 领取大额优惠 / 礼券 / 其它运营福利
```

大礼包的目的：

- 给持续完成平台行为、但不以学习 / 拿证为目标的学生提供可感知回报；
- 避免徽章只有展示意义；
- 让广告、活动、签到等运营行为有长期积累价值。

礼包由运营侧配置，研发只提供基座。首期不建设复杂积分商城或礼包交易系统。

运营至少需要能够配置：

- 礼包名称与说明；
- 有效时间；
- 徽章门槛（数量或指定组合）；
- 礼包库存 / 是否已领完；
- 领取后的权益承接方式。

具体礼包金额、组合数量和履约方式不在本 PRD 写死。

## 6. 广告场景基座（T038 / T039 / T040）

平台不控制广告平台的实际竞价和素材投放，因此首期只做一层很薄的“广告场景配置”，不建设广告投放后台。

建议统一抽象：

```text
AdScene
- sceneKey
- enabled
- adType
- triggerMode
- skipPolicy
- frequencyRule
- businessAction
```

运营侧控制的是“这个位置是否启用、什么时候触发、属于什么业务场景”，不是控制每一条广告素材。

### 6.1 T038｜福利领取激励广告 + 权益详情信息流

首期保留两类广告：

1. 免费福利领取前的激励广告；
2. 权益详情页中的信息流广告位。

关键规则：

```text
完成激励广告
→ 只代表完成领取条件
→ 再执行福利领取 / 发放动作
→ 发放成功才显示领取成功
```

因此必须区分：

- 广告完成；
- 福利领取请求；
- 福利领取成功 / 失败。

不能把“广告播放完成”直接等同于“卡券已经发放成功”。

原型阶段允许模拟发放结果，但真实接入发券 / 权益 API 后必须保留失败与重试状态。

T035 已定义的权益到账方式继续有效；T038 不重新定义订单、库存或发券系统。

### 6.2 T039｜机会板块信息流广告

职位 / 企业列表允许插入原生信息流广告，广告卡应：

- 与列表自然滚动；
- 明确标识“广告”；
- 不伪装成真实职位或企业；
- 不改变真实职位 / 企业的排序事实。

原型当前采用“第二张真实卡片之后插入一张广告”用于验证布局，可以作为首期默认位置；后续真实广告 SDK 接入后，插入频率由轻量场景配置决定。

平台不承诺控制每一条广告素材；如广告 SDK 提供行业过滤 / 合规过滤能力，应优先使用，避免广告内容破坏机会板块的基本信任感。

### 6.3 T040｜常规 App 开屏广告

“开屏广告”的产品定义应是 **App 冷启动场景广告**，而不是永久绑定 `/welcome` 页面。

首期规则：

- 正常冷启动可以展示；
- 无广告填充时直接进入 App，不阻塞启动；
- 必须提供明确跳过能力；
- 带明确业务回跳目标的注册回跳、赛事 / 报名 / 邀请等 deep link 不应被开屏广告破坏；
- 频控由广告场景配置决定，不在页面代码中永久写死。

如果当前原型技术上只能实现为 `/welcome` 前置广告，则应视为“开屏广告的原型模拟”，不能据此把正式业务定义改成欢迎页广告。

## 7. 每日打卡（T041）

每日打卡从新手任务中解耦，成为长期任务 / 行为入口。

### 7.1 基本规则

- 新手任务可以引导用户去完成首次打卡；
- 但新手任务完成后，每日打卡继续长期存在；
- 打卡事实只有一份，任务中心、新手任务、徽章规则都读取同一事实；
- 连续打卡规则、补签与连续奖励后续再定，不在本 PRD 扩展。

### 7.2 与广告关系

按第 2.5 节采用可配置策略，不把“看广告才能签到”永久写死。

当场景为“广告必选”时，跳过广告意味着本次签到条件未完成；前台文案应表达“放弃本次签到 / 未完成条件”，不要错误写成“放弃奖励”却同时取消签到。

当场景为“广告额外奖励”时，应先记录签到成功，再独立处理广告奖励。

## 8. 事实源与数据原则

徽章系统只做规则判断与成就发放，不复制其它领域事实。

事实来源示例：

| 事实 | 真相源 |
| --- | --- |
| 课程完成 / 学习进度 | 课程学习记录 |
| 小测 / 结业考试 | 课程考核记录 |
| 赛事身份 / 成绩 / 项目进度 | 赛事领域 |
| 每日打卡 | 任务 / 打卡事实 |
| 广告完成 | 广告 SDK 完成回调 / 服务端可验证事件 |
| 权益领取 | 权益 / 福利领域 |
| 可信证书 | 可信证书签发事实 |

徽章记录只保存必要引用，例如 `sourceType + sourceId + ruleId + grantedAt`，不能另建一套课程、赛事、权益或证书状态。

## 9. PC 运营端最小基座

首期只提供支持业务运行的薄配置能力，不另建庞大运营系统。

建议至少包含四组配置：

1. **徽章定义**：名称、图形、来源类型、品相、达成条件、启停；
2. **证书资格规则**：可信课程 + 徽章组合 + 小测 / 结业考核；
3. **礼包规则**：礼包内容、时间、徽章门槛、库存 / 状态；
4. **广告场景**：场景启停、广告类型、触发模式、简单频控 / 跳过策略。

广告素材、广告主、竞价与投放算法不由本后台管理。

## 10. T038–T042 收口要求

| 任务 | PRD 收口要求 |
| --- | --- |
| T038 | 保留福利激励广告与权益详情信息流；明确“广告完成 ≠ 福利发放成功” |
| T039 | 机会列表允许自然信息流广告；广告与真实职位 / 企业明确区分 |
| T040 | 正式定义为 App 冷启动开屏广告；欢迎页前置仅可作为原型模拟 |
| T041 | 每日打卡与新手任务解耦；广告关系改为可配置，不永久硬绑定 |
| T042 | 徽章来源与品相拆成两个维度；徽章本身无可信等级；可信课程为证书硬门槛；低 / 高品相徽章均可进入统一证书资格规则；礼包作为第二价值出口 |

后续任务卡与实现记录如与本 PRD 冲突，以本 PRD 的已确认业务规则为准，并在修改时保留原任务历史记录。

## 11. 当前仍待收口的产品参数

以下内容不阻塞本 PRD 成为 T038–T042 的产品骨架，但施工到真实规则时必须继续确认：

1. 徽章最终品相命名、层级数量与视觉体系；
2. 首批正式徽章清单；
3. 可信证书统一规则中的 X / Y 数量、指定徽章组合；
4. 关卡小测、结业考试的具体题量、及格线、重考规则；
5. 哪些现有 / 新增课程正式进入“可信课程”范围；
6. 可信证书正式对外展示的签发主体、认证名称与资质口径；
7. 大礼包首批内容、门槛、库存与履约方式；
8. 每日打卡各阶段采用 A / B / C 哪种广告策略；
9. 各广告场景真实 SDK / Provider、频控与 no-fill 策略；
10. 普通徽章进入可信空间 / 简历时的展示范围与隐私规则。

这些参数应由产品 / 运营逐项配置或确认，不由施工线程自行发明。
