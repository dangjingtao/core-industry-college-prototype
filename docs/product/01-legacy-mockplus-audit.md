## 2. 结论先行

旧重构的以下工程结论仍然成立：

- 140 个旧页面都建立了旧→新去向；
- 66/66 semantic routes 在旧重构 App 中有明确承接；
- RouteProbe 清零；
- 五条母动线通过真实 Chromium 回归；
- 旧重构的公共平台 / 多赛事身份 / 创赛工坊 / 长期资产骨架是正确方向。

但是直接检查原始 Mockplus 包后必须修正一句话：

> **“140/140 页面有去向”不等于“旧原型功能 100% 没缩水”。**

页面合并时有一批二级操作、字段、外部 handoff 和业务语义被省略、替换或冻结。

因此以后不能只做 route audit；还需要做 **feature-level audit**。

## 4. 高风险语义替换：不是简单“漏页”，必须产品确认

### 4.1 学力值：旧原型是“可收支积分”，旧重构变成“成长分数”

这是本次复核最值得警惕的语义变化之一。

#### 旧原型中的学力值

旧 `学力值明细` 明确有：

- 学力值余额；
- 今日收获；
- 全部 / 收入 / 消耗；
- 每日签到等流水。

旧 `兑换中心` 明确有：

- 搜索可兑换项目；
- 类别：全部 / 课程 / 入场券 / 虚拟权益；
- 默认 / 销量 / 学力值排序；
- “200 学力值”；
- 已兑换人数。

旧课程还存在：

> “确认消耗 200 学力值兑换该课程吗？你目前还有 1280 学力值”

旧日常任务 / 核心任务明确用于“赚学力值”。

#### 旧重构中的学力值

旧可交互重构把 `GrowthScorePage` 改成类似：

```text
基础账号 +60
已完成学习 +N
真实投递 +N
= 当前学力值
```

它是一个“成长分数”，不再有余额、收入、消耗、兑换经济。

课程兑换也被改成“对应权益 entitlement 解锁”。

#### 判断

这不是普通的 UI 重构，而是**业务模型替换**。

不能默认为旧积分经济已经被产品废弃。

需要明确回答：

- 学力值以后到底是积分、成长分还是两者都不是？
- 是否仍然能消费？
- 是否仍用于课程 / 权益兑换？
- 日常 / 核心任务的奖励对象是什么？
- 如果旧积分模型废弃，旧兑换中心如何迁移？

在答案明确前，不要继续扩大 GrowthScore 实现，也不要机械恢复商城。

---

### 4.2 旧“兑换中心”与当前“权益系统”不是同一个产品

旧兑换中心偏商城 / 积分兑换：

- 搜索；
- 分类；
- 销量；
- 学力值排序；
- 兑换课程 / 入场券 / 虚拟权益。

当前重构的权益系统更强调：

- 平台 / 赛事 / 企业 / 活动来源；
- eligibility；
- claimed / used / expired；
- 不做商城主叙事。

#### 判断

当前权益方向与后来业务讨论更一致，但旧兑换经济是真实历史能力。

需要产品明确：

- 是彻底废弃旧兑换中心；
- 还是把“可兑换商品”作为权益的一种发行方式；
- 或未来“创域”承接活动 / 权益 / 兑换的部分能力。

未确认前不应把旧兑换中心简单标成“已完全覆盖”。

### D08｜主体管理

旧原包真实存在完整流程：


继续冻结是对的，直到产品和后台规则明确。

## 8. 旧页面映射中“看起来覆盖、实际需复核”的典型模式

以后做页面审计要特别警惕以下情况：

### “合并到详情页”

例如工商信息被写成 `/companies/:companyId?tab=business`，但实际页面没实现对应内容。

### “保留路由”

例如 `/assets/verification` 路由存在，但旧扫码 / 文件验真能力没保住。

### “改成另一种业务语义”

例如：

- 学力值积分 → 成长分数；
- 抖音 / 快团团第三方账号 → 邮箱 / 企微 / 微信绑定；
- 学力值课程兑换 → entitlement 权益解锁。

### “外部系统 handoff 被原型模拟替代”

例如：

- 企微人工客服；
- 公众号阅读全文；
- 微信发送资料；
- 官方验真平台。

这些在中保真里可以模拟，但必须保留产品意图和出口，不应悄悄消失。

## 9. 当前审计结论分级

### 可以直接补，不需重做产品骨架

1. 企业工商信息；
2. 退出登录；
3. 证书 / 成绩下载保存入口；
4. 资料保存到本地 / 外部分享表达；
5. 公众号阅读全文出口；
6. 人工客服最终 handoff 表达。

### 需要先统一数据模型再补

1. Onboarding / Profile / 手机号 / 生日 / 地区 / 用户类型 / 问卷；
2. 长期简历结构化教育字段；
3. 团队减员 / 变更流程。

### 必须产品确认后再动

1. 学力值到底是积分还是成长分；
2. 旧兑换中心是否废弃；
3. 第三方账号到底指电商/内容平台账号还是登录绑定；
