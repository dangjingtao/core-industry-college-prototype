# 14｜T035 兑换中心 / 手机号绑定体验

> 状态：原型规则已收口  
> 日期：2026-08-24  
> 范围：移动端兑换中心

## 结论

兑换中心不再采用“列表里直接兑换”的表达，而是统一走：

```text
兑换中心
→ 权益 / 课程详情
→ 看清消耗与到账方式
→ 确认兑换
→ 成功结果
```

用户在确认前必须能看到：

- 兑换内容；
- 所需学力值；
- 当前可用学力值；
- 兑换后预计剩余；
- 到账方式。

## 手机号规则

线上会员 / 卡券类权益在当前原型中使用**当前登录账号已验证手机号**作为到账手机号。

兑换页：

- 不再额外提供一个临时手机号输入框；
- 未绑定 / 未验证手机号时提示先完成绑定；
- 已绑定时展示脱敏手机号；
- 不在 T035 内扩展频繁换绑、历史卡券迁移或转赠规则。

课程兑换不强制手机号：

```text
学力值兑换课程
→ 课程直接进入当前学习账户
```

入场券 / 其它账号权益当前只验证“进入当前账号权益记录”的交互，不额外定义手机号要求。

> 哪些具体权益最终必须绑定手机号仍应由单个权益配置决定。T035 原型只用“线上权益”类别验证默认手机号到账体验，不把它升级成所有权益的永久规则。

## 与 T034 的关系

兑换中心的课程列表必须与 T034 的课程价值层级一致。

因此当前兑换中心只前台展示真正 `creditRequired` 的课程，不继续把已经免费化的旧课程包装成“课程商品”。

旧兑换链接仍做兼容：若旧链接指向的课程已经免费，详情页明确提示“当前无需学力值兑换”，直接进入课程。

可信证书课程继续保持：

```text
高学力值课程
+ 可信证书标识
```

不在 T035 重新定义证书规则。

## 失败状态

原型只保留用户能理解的三类失败：

- 学力值不足；
- 已兑完；
- 需要手机号但当前账号未绑定 / 未验证。

不扩展库存锁、订单超时、支付补偿、券码重试等后台状态机。

## 原型边界

- 课程兑换调用现有课程报名 / 学力值扣减逻辑；
- 非课程权益用前端原型状态记录兑换结果；
- 不实现真实库存服务、发券服务或订单系统；
- 不在本任务决定转赠、退款、过期补偿和手机号换绑后的历史资产迁移。
