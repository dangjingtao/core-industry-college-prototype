## 1. 结论（TL;DR）

运营沙盒 V2.0 是一份**长期完整愿景（蓝图）**，不是当前可施工范围。

- 它与已确认的首期「经营决策体验」Demo 不构成对错冲突，而是**首期范围 vs 长期愿景**的关系；
- V2.0 中约一半内容可作为长期方向并入产品文档；另有约一半触碰当前未决业务模型或产品红线，**必须先由产品/会议决策后才能定**；
- 首期 Demo 范围与现原型 5 个模块结构不应被 V2.0 推翻；
- 建议把 V2.0 拆成三档（可并入愿景 / 需产品决策 / 暂缓）维护，并建立决策门槛清单。

## 2. 文档定位判断

### 2.1 V2.0 是什么

V2.0 把首期刻意排除的能力基本全部拉回，并新增：

- 赛中/赛后 6 项 AI 能力：AI 海报设计、AI 智能组队、AI 会议纪要、AI 数据复盘、AI 技能雷达；
- 7.3 AI 教练人格设计（有名字、性格、语气变化）；
- 8 市场事件系统（危机 / 机遇 / 中性 / 隐藏事件 + 概率 / 条件 / 赛季触发）；
- 9.1 决策引擎（ΔKPI 多维联动模型）；
- 9.2 反作弊设计（算力限制、决策多样性、行为指纹、区块链存证）；
- 10 用户动线（新手动线 + 每日运营节奏）；
- 11 从沙盒到就业闭环（能力画像 → 自动简历 → 企业人才库 → 面试直通卡 → 实训匹配 → 数据飞轮）；
- 12 实施路线图（P0–P5）。

### 2.2 V2.0 的长处

- 结构完整：从能力、玩法、技术、动线到商业闭环都有展开；
- 有明确方向感：把"沙盒 → 能力 → 就业"串成了完整故事；
- 市场事件系统对玩法深度有真实价值，是模拟模块的正确演进方向之一。

### 2.3 V2.0 的短板

- 没有区分"现在做什么 / 以后做什么"，未提及已确认的「经营决策体验」Demo 与现原型 5 个模块；
- 决策引擎只有公式概念，缺少 KPI 定义、参数边界、衰减系数、随机因子范围与可复现性说明；
- 每日运营节奏接近强制每日任务循环，与产品"高粘度优先、不强制高频"的原则冲突；
- 默认已挂接正式赛事阶段（初赛 10% / 复赛 20% / 决赛 30%、"双11模拟战"），但当前沙盒不是正式赛事。

## 3. 与已确认首期方案的关系

| 维度 | 已确认首期（06 + 05 + 现原型） | V2.0 |
|---|---|---|
| 产品名称 | 经营决策体验 | 运营沙盒 |
| 定位 | 独立活动 Demo，不进一级导航 | 长期实战训练 + 就业闭环 |
| 场景 | 5 个 iframe 模块 | 社区团购起步，后续多场景 |
| 计分 | 不保存、不评价 | 多维 KPI + 排名 + 能力画像 |
| AI | 不作为首期卖点 | AI 教练 / 6 项 AI 能力为卖点 |
| 经济 | 不接入学力值 / 算力 / 签到 | 算力限制 + 双货币 |
| 关联 | 不关联简历 / 证书 / 长期资产 | 能力画像 → 简历 → 企业对接 |

对应关系：现原型 5 个模块已覆盖 V2.0 P0–P1 的"场景数量"层，但多维 KPI、AI 反馈深度未达到；V2.0 的 P2 起与首期明确排除项直接冲突。

## 4. 分模块评估

### 4.1 A 档｜与已确认方向一致，可作为长期愿景并入

| V2.0 能力 | 判断 | 依据 |
|---|---|---|
| 赛中 AI 海报设计 | ✅ 赛事上下文 AI 方向 | 对齐"创赛工坊是赛事专属 AI，不是全局工具箱"；工坊 T013C 已有 S5 PPT 生成，海报为同类能力方向 |
| 赛后 AI 数据复盘 | ✅ | 对齐 00 主纲"赛后出口 / 经验沉淀 / 长期资产" |
| AI 技能雷达 / 能力画像 | ⚠️ 仅"客观量化事实"可并入 | 与 T017 长期简历 / 个人成长档案重叠；百分比能力评分见 B 档 |
| 企业对接（人才库 / 实训匹配 / 面试直通卡） | ⚠️ 方向可行 | 对齐 00 企业角色（营销 / 增长人才、实习）与"参赛 + 就业"主轴；必须学生自选、不做不透明评分 |
| 市场事件系统 / 决策引擎 | ✅ 模拟玩法深度 | 属于沙盒模块内部玩法演进，不改变平台模型、不建第二真相源 |
| AI 会议纪要 | ⚠️ 需限定范围 | 只能作为赛事 / 团队上下文内 AI，不能升级为全局 AI 助手 |

### 4.2 B 档｜撞红线，需产品决策后才能定

1. **算力限制 + "购买算力需完成课程任务"（9.2）+ P2 双货币**
   - 触碰 F04 Decision A（学力值 / 算力经济未决）；
   - "课程任务 → 算力"是跨域奖励关系，属 D03 未决范畴；
   - 施工线程不得自行选择经济模型。
2. **能力画像百分比评分（选品能力 80% 等）**
   - 正撞 AGENTS.md 红线"不构造对学生不透明的 AI 人才评分"；
   - 也撞旧审计结论"不要因为旧图里有雷达图，就重构一个无依据的 AI 人才评分"；
   - 必须先定义：数据来源、解释方式、真实业务目标。
3. **AI 智能组队（技能互补匹配最佳队友）**
   - 是对学生画像的匹配算法，透明性、同意机制、赛事范围、与 D08 团队 / 主体边界均未定义。
4. **行为指纹 / 异常行为触发人工审核（9.2）**
   - 对学生行为做反作弊画像，属敏感数据处理；
   - 文档只提"数据透明"，但采集范围、保留期、人工审核依据未定义。
5. **区块链存证（9.2）**
   - 原型阶段不必要（AGENTS 原则：不为原型引入不必要后端 / 重架构）；
   - 可降级为"决策过程可导出审计记录"的方向。

### 4.3 C 档｜文档自身缺口 / 设计风险

1. 与已确认首期 / 现原型的关系完全没提，没有"从 Demo 升级"的描述路径；
2. 决策引擎公式不可复核：缺 KPI 定义、参数边界、边际递减、"审美疲劳"衰减曲线、随机因子范围、可复现性；一旦进正式赛事，05 协议要求"规则透明可复核"，当前不满足；
3. 每日运营节奏（8:00–21:00 六段）接近强制每日任务循环，与 00"高粘度比每天高频更重要"、06"避免连续签到 / 强制每日任务"冲突；
4. 初赛 / 复赛 / 决赛概率、"双11模拟战"默认沙盒已挂正式赛事阶段，当前阶段概念未定义；
5. "自动生成运营能力简历"与 T017"自动聚合客观事实、不构造不透明 AI 评分"存在口径张力，需统一；
6. 排名 / 等级 / 徽章 / 实时对战全做会推动产品气质走向"游戏化培训平台"，与平台专业定位冲突（05 命名建议已明确避免"AI 运营沙盒""运营实战训练""经营能力测评"等承诺性表述）。

## 5. 决策门槛清单

以下项必须先由产品 / 会议明确决策，施工线程不得自行落地（无论用 demo 还是正式形态）：

| 编号 | 事项 | 必须先回答的问题 | 关联未决 |
|---|---|---|---|
| G1 | 算力 / 学力值经济 | 沙盒内是否引入余额、消耗、奖励、兑换；与课程任务是否绑定 | F04 A、D03 |
| G2 | 能力画像百分比评分 | 数据来源是什么、如何解释、真实业务目标；能否只保留客观量化指标 | AGENTS 红线、旧审计 |
| G3 | AI 智能组队匹配 | 是否对学生画像做匹配；透明性与同意机制；赛事范围 | D08、团队语义 |
| G4 | 行为指纹 / 异常审核 | 采集范围、保留期、审核依据、是否对用户透明 | 数据合规 |
| G5 | 区块链存证 | 是否确需；原型阶段是否降级为可导出审计记录 | 工程边界 |
| G6 | 排名 / 等级 / 徽章 / 双货币 | 是否进入沙盒；是否会造成"游戏化培训平台"气质 | 首期排除项 |
| G7 | 自动生成能力简历 | 与 T017 客观事实聚合口径如何统一；是否引入 AI 评分 | T017、AGENTS 红线 |
