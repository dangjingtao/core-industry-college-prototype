# 09｜承诺书流程（T030）

> 状态：Owner 已确认 / 原型收口依据  
> 日期：2026-08-24  
> 适用：三创赛 PC 报名门户

## 1. 已确认结论

两份承诺书都保留：

1. 学生 / 参赛团队承诺书；
2. 指导老师承诺书。

不做页面内电子签名。统一流程为：

```text
生成 / 下载
→ 打印
→ 手写签字
→ 上传签字后的文件
→ 两份都上传后完成本步骤
```

## 2. 原型只表达必要状态

每份承诺书只需要四个用户可感知状态：

- 待生成；
- 可下载；
- 已签字待上传；
- 已上传。

不在当前原型继续设计文件审核、版本管理、签名识别、OCR、电子签章、文件有效期等后台细节。

## 3. 两份文件的关系

### 学生 / 团队承诺书

沿用当前项目标题、项目摘要、创新点、创意点、创业点等报名内容生成。

### 指导老师承诺书

保留入口文案：

> 下载指导老师承诺书模板

老师承诺书复用当前团队 / 项目信息，不要求指导老师再录一遍项目内容。

指导老师信息可以后置补充，不阻塞前面的团队报名与学校审核。

## 4. 页面结构

学校审核通过后进入承诺书页：

```text
项目信息
↓
学生 / 团队承诺书
  下载 → 打印签字 → 上传
↓
指导老师承诺书
  下载模板 → 打印签字 → 上传
↓
两份均已上传
→ 完成报名
```

页面应明确告诉队长：上传的是已经完成手写签字的文件。

## 5. 完成条件

不能再使用“生成承诺书”作为完成报名的条件。

正确条件：

```text
学生 / 团队承诺书已上传
AND
指导老师承诺书已上传
→ 可以完成报名
```

如果只上传其中一份，页面继续显示另一份待处理，不进入完成态。

## 6. 当前不做

- 页面内电子签；
- 指导老师独立填写第二套项目资料；
- 复杂文件审批状态；
- 多版本文件管理；
- 自动识别签字真实性；
- 老师端单独再造一套承诺书制作流程。

教师工作台后续如需要，只展示当前团队承诺书材料及必要审核信息即可，具体放到 T032 处理。
