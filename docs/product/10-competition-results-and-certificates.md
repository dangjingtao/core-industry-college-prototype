# 10｜T031 业绩报告 / 证书阶段与领取体验

> 状态：原型设计已收口  
> 日期：2026-08-24  
> 范围：学生可见的赛事结果与证书页面，不设计签发后台或完整状态机。

## 1. 已确认原则

1. **业绩报告是赛事结果领取入口，不是学生上传数据入口。**
2. 校赛、省赛、国赛等阶段分别展示自己的报告状态。
3. **业绩报告、晋级结果、证书签发是三件不同的事。**
4. 普通电子证书与官方可信证书分开表达。
5. 可信证书只在赛事规定的高阶段 / 总决赛等满足资格时出现领取能力；当前阶段不满足时，不展示伪领取入口。

## 2. 原型流程

```text
赛事阶段结束 / 结果发布
        ↓
业绩报告可领取
        ↓
用户领取 / 下载

晋级结果
单独公布，不由“报告可领取”推断

普通电子证书
按赛事阶段独立签发

可信证书
仅满足高阶段资格时出现
```

## 3. 业绩报告页

原型只展示三个阶段：

- 校赛：示例为“可领取”；
- 省赛：示例为“待生成”；
- 国赛：示例为“未开放”。

用户点击“领取报告”后，页面切换为“已领取 / 可下载”。

页面必须明确：

> 报告由赛事结果生成，不需要学生上传业绩数据或附件。

另设“晋级结果”区域，与报告卡片分离。即使报告已经可以领取，晋级仍可以是“待公布”。

## 4. 证书页

### 普通电子证书

- 可按校赛 / 省赛 / 国赛分别展示；
- 示例保留“校赛电子证书可下载”；
- 下载后可表达“已保存至长期资产”。

### 可信证书

- 与普通电子证书视觉和文案分层；
- 当前原型阶段不满足高阶段资格，因此只说明规则；
- **不展示可点击的“领取可信证书”按钮。**

## 5. 不做的内容

本卡是产品原型，不继续展开：

- 签发后台；
- 证书撤销 / 重签完整状态机；
- 可信证书 API；
- PDF 真实生成；
- 各赛道具体发证时间配置；
- 各阶段真实晋级名单。

这些在真实业务规则确定后由实现阶段补充。

## 6. 原型验收

用户应能一眼看懂：

- 我不是来上传“业绩报告”的；
- 哪个阶段的报告现在能领；
- 报告可领不等于晋级；
- 晋级不等于证书已经签发；
- 普通电子证书和可信证书不是同一种凭证。
