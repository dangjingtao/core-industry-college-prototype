## 2. P0｜下一轮应优先处理

### GAP-01｜统一学生主档 + Onboarding / Profile / Questionnaire

现状问题：

- 旧 Mockplus 有完整手机号、验证码、昵称、性别、生日和 8 组问卷；
- 旧重构只剩学校 / 专业 / 城市 + 四个关注项；
- 业务访谈又明确把“注册 + 报名 + 问卷”视为当前最现实的学生数据采集方式。

#### 需要先回答

1. 哪些是 App Account 的长期主档字段？
2. 哪些字段注册必填？
3. 哪些字段只做可跳过问卷？
4. 哪些字段可以从赛事报名回流，不应重复问？
5. 哪些字段由创赛工坊后续问卷补充？
6. 学校、专业、地区、身份类型等是否形成统一字段枚举？

#### 最低交付

- `StudentProfile` / 等价主档模型；
- onboarding 与 `/me/profile` 使用同一真相源；
- 手机号 / 验证码可用中保真模拟，不必接真实短信；
- 保留旧问卷中仍有价值的采集维度；
- 允许后续报名 / 工坊复用，不建立问卷答案孤岛。

### DECISION-01｜学力值到底是什么

这是下一轮最重要的业务决策之一。

#### 旧原型

学力值 = 可收入 / 可消费 / 有余额 / 有流水 / 可做课程兑换的积分。

#### 旧重构

学力值 = 根据基础账号、学习、投递计算的成长分数。

两者语义冲突。

#### 必须确认

选择之一：

A. **保留积分经济**  
恢复余额、流水、收入/消耗、任务奖励、兑换能力。

B. **废弃积分经济，只保留成长分**  
则需要明确旧兑换中心、任务奖励、课程兑换全部如何替代，并避免继续沿用“学力值”造成误解。

C. **积分与成长分拆成两个对象**  
如果业务确实两者都要，必须使用不同命名和不同状态模型。

施工线程不得自行选择。

## 5. 冻结与部分解冻边界

### D03｜任务体系（聚合层部分解冻）

必须先定义：

```text
平台任务
赛事任务
企业任务
权益任务
创赛工坊 Task Runtime
学力值/奖励
```

之间的关系。

仍未确认的部分：

- 不把日常任务列表直接抄回来；
- 不把工坊 task 当全局 task；
- 不自行恢复“看广告赚学力值”。

#### 已确认的局部边界（2026-08-17）

首页可以加入“任务专区”聚合模块，但只展示已有流程的下一步，并直接跳转到现有赛事工作区、赛事内创赛工坊、课程、投递或机会页面。

后续确认补完独立 `/tasks`：页面读取现有 domain store 并归一展示状态，不持有第二份 task 真相源。该决定解除 `/tasks` 的聚合层 blocked 状态，但不恢复旧日常/核心/企业任务，也不定义统一奖励关系。

- 学生 Profile / 简历中的邮箱仅作为可编辑的联系方式展示字段保留，不作为登录账号身份。

施工：`apps/mobile/src/features/auth/AuthPages.tsx`、`apps/mobile/src/features/platform-support/SupportPages.tsx`、`apps/mobile/src/app/App.tsx`、`apps/mobile/src/routes/registry.ts`。
