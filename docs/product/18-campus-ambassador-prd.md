# 18｜核心大使计划 PRD

> 状态：Draft / 待评审  
> 日期：2026-08-26  
> 适用：学生 App + 现有 PC 运营管理端  
> 目标：用一套轻量规则完成「招募核心大使 → 组队点亮 → 团队推广 → 查看成果 → 运营激励」闭环。

---

## 1. 需求目标

运营方按一期活动，在学校内招募核心大使并发展推广团队。

首版完成四件事：

1. 运营方创建一期「核心大使计划」，向参与学校提供大使招募二维码；
2. 学生扫码申请成为核心大使，招募推广伙伴，达到 4 人后点亮身份；
3. 团队点亮后，全员使用各自专属推广码带来新用户注册；
4. 核心大使查看本团队推广成果，运营方在 PC 端查看全局数据并处理团队激励。

本功能属于长期账号上的运营活动身份，不属于某一场赛事身份。每期活动结束后团队自动结束，仅保留历史记录。

---

## 2. 角色与统一用词

| 对象 | 产品用词 | 说明 |
| --- | --- | --- |
| 活动 | 核心大使计划 | 按期运行，有开始/结束时间 |
| 团队负责人 | 核心大使 | 每个团队只有 1 位 |
| 大使状态 | 待点亮 / 已点亮 | 身份名称不变化，只变化状态 |
| 普通团队成员 | 推广伙伴 | 不获得大使身份 |
| 大使用于组队的码 | 团队招募码 | 只用于加入推广团队 |
| 全员用于拉新的码 | 专属推广码 | 只用于拉新注册归因 |
| 原“业绩” | 推广成果 | 学生侧统一采用较友好的表达 |
| 成功拉新指标 | 有效新增 | 新用户完成注册后计数 |
| 运营奖励 | 团队激励 | 发给核心大使，平台不处理内部再分配 |

## 3. 整体流程

```text
【PC 运营端】
创建核心大使计划
→ 选择学校 / 配置活动时间
→ 每所学校生成大使招募二维码
        ↓
【学生 App】
学生扫码
→ 登录 / 注册
→ 填写申请表 + 同意条款
→ 核心大使 · 待点亮
→ 获得团队招募码
→ 邀请推广伙伴
→ 1 位核心大使 + 至少 3 位推广伙伴
→ 团队点亮
→ 核心大使 · 已点亮
→ 全员获得各自专属推广码
→ 专属推广码 → 下载 App → 新用户注册成功
→ 形成有效新增
        ↓
【学生 App】
核心大使查看团队推广成果
推广伙伴只负责推广，不查看成果数字
        ↓
【PC 运营端】
查看活动 / 学校 / 团队推广成果
→ 处理团队激励
        ↓
活动结束
→ 团队自动结束
→ 招募码 / 推广码失效
→ 保留历史记录
```

## 4. 学生 App 逻辑

### 4.1 核心大使申请

运营方为参与学校提供对应的大使招募二维码。

学生扫码后：

1. 未登录用户先登录或注册，完成后回到申请流程；
2. 填写运营要求的申请字段；
3. 阅读并同意相关条款；
4. 提交成功后直接获得「核心大使 · 待点亮」身份，首版不增加人工审核；
5. 系统生成该大使的「团队招募码」。

同一用户在同一期活动中只能属于一个推广团队，不能同时成为其它团队的大使或推广伙伴。

### 4.2 推广伙伴加入

核心大使分享团队招募码。

- 新用户可注册后加入；
- 已注册老用户也可加入；
- 前提是当前未绑定本期其它推广团队；
- 加入后成为「推广伙伴」；
- 活动期间不可主动退队、不可换队。

团队人数无上限，点亮后仍可继续招募。

### 4.3 团队点亮

点亮条件固定为：

> **1 位核心大使 + 至少 3 位推广伙伴，即团队总人数达到 4 人。**

点亮前：

- 核心大使显示「待点亮」；
- 展示组队进度；
- 只开放团队招募；
- 不开放任何人的专属推广码。

点亮后：

- 核心大使显示「已点亮」；
- 团队进入正式推广状态；
- 核心大使和所有推广伙伴获得各自独立的专属推广码；
- 后续新加入已点亮团队的推广伙伴，也获得自己的专属推广码。

### 4.4 专属推广码与有效新增

```text
专属推广码
→ 扫码
→ App 下载流程
→ 安装
→ 新用户完成注册
→ 系统识别推广来源
→ 对应推广人员 +1 有效新增
```

业务口径：

- 从扫码开始必须保留推广来源；
- 每个有效新增能够关联活动、团队和推广人员；
- 仅此前未注册过 App 的新用户注册成功计入有效新增；
- 已注册用户扫码不重复计入；
- 安装归因的具体技术方案由研发确定，本 PRD 不锁定实现方式。

### 4.5 推广成果权限

**核心大使可看：**

- 团队人数；
- 团队有效新增总数；
- 核心大使及各推广伙伴对应的有效新增数量；
- 运营最终确认的必要推广明细。

**推广伙伴可看：**

- 自己已加入的团队；
- 当前活动 / 团队状态；
- 自己的专属推广码。

**推广伙伴不可看：**

- 自己的有效新增数量；
- 其他成员推广成果；
- 团队有效新增总数；
- 排行榜。

### 4.6 活动结束

活动结束后：

- 团队自动结束；
- 团队招募码和专属推广码失效；
- 不再新增推广成果；
- 解除本期团队绑定限制；
- 保留本期身份、团队与推广成果记录；
- 后续新活动可重新申请核心大使或加入新团队。

## 5. PC 运营后台逻辑

核心大使计划应接入**现有 PC 管理端控制面**，不另起一套独立后台。

首版运营心智保持三层：

```text
活动列表
→ 活动详情
→ 团队详情
```

### 5.1 活动列表

至少展示：活动名称、时间、状态、覆盖学校数、核心大使数、已点亮团队数、有效新增总数。

### 5.2 创建 / 编辑活动

首版配置：

- 活动名称；
- 开始 / 结束时间；
- 参与学校；
- 大使申请表字段；
- 活动条款。

团队点亮门槛首版固定为「1 位核心大使 + 3 位推广伙伴」，不做复杂规则配置器。

### 5.3 学校与大使招募码

- 每所学校生成独立的大使招募二维码；
- 二维码关联「活动 + 学校」；
- 支持查看 / 下载二维码；
- 可查看该学校产生的大使、团队与推广数据。

### 5.4 活动详情

顶部展示活动整体数据：覆盖学校、核心大使、已点亮团队、推广伙伴、有效新增。

下方团队列表至少包含：核心大使、学校、团队状态、团队人数、有效新增、激励状态，并提供基础筛选。

### 5.5 团队详情

展示：

- 核心大使基本信息和申请信息；
- 学校、团队状态、团队人数；
- 团队有效新增总数；
- 成员列表及每人有效新增；
- 必要推广明细；
- 简单团队激励状态。

运营端可查看成员级推广成果；推广伙伴 App 端不可查看。

### 5.6 团队激励

平台首版只负责：

- 提供团队推广成果；
- 识别对应核心大使；
- 如业务需要，记录简单的「未处理 / 已处理」状态。

平台不计算团队内部个人分成，不给推广伙伴逐人结算，也不干预大使如何分配激励。

## 6. 前后台联动

| 事件 | App 结果 | PC 结果 |
| --- | --- | --- |
| 创建活动并配置学校 | 对应学校招募码可进入申请链路 | 生成活动、学校与招募码 |
| 大使申请成功 | 显示「待点亮」并获得团队招募码 | 新增大使与团队记录 |
| 推广伙伴加入 | 团队人数和点亮进度变化 | 团队人数同步变化 |
| 团队达到 4 人 | 大使变为「已点亮」，全员开放专属推广码 | 团队变为推广中 / 已点亮 |
| 新用户有效注册 | 大使端推广成果更新 | 活动 / 团队 / 成员数据同步更新 |
| 活动结束 | 二维码失效、团队结束、历史保留 | 活动和团队转历史状态 |

---

## 7. 首版不复杂化

- 不做多级代理、上下级大使或子团队；
- 不做推广伙伴排行榜；
- 不做活动期间退队 / 换队；
- 不做永久大使等级；
- 不做真实财务结算与个人分账；
- 不把推广成果混入赛事成绩 / 赛事身份；
- 不新建与现有账号、学校、PC 控制面冲突的第二真相源。

进入最终设计 / 开发前，仅需继续补齐：

1. 大使申请表具体字段；

4. 团队激励规则，以及是否启用后台发放状态；
5. 推广明细最终展示粒度。
