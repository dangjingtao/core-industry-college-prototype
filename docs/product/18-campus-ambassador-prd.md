## 0. V1.1 本次修订

本次为原 PRD 的直接修订，不另起补充 PRD。V1.0 已完成的业务骨架继续有效，以下规则以 V1.1 为最新口径：

1. **所有用户可见、运营可见的身份名称与活动展示名称统一调整：**
   - 「核心大使」→ **「校园大使」**；
   - 「推广伙伴」→ **「校园推荐官」**；
   - 「核心大使计划」→ **「校园大使计划」**；
   - 「核心大使计划活动条款」→ **「校园大使计划活动条款」**；
   - 技术内部 `ambassador / partner`、`coreAmbassadorAccountId`、既有函数 / 类型 / 路由 / 文件名等技术命名不要求随展示名迁移。
2. 继续使用现有「校园大使申请问卷」，后台补充完整问卷配置与**团队申请问卷答案视角**；校园推荐官加入团队时不新增第二份问卷。
3. PC 后台增加**周度团队运营视角**：按周查看团队拉新效果，支持列表、团队详情以及「指定团队 / 全部团队」数据导出。
4. 团队增加**内部团队名**：后台可指定；未指定时自动生成可读且唯一的兜底名称；团队名与团队招募码对应的团队绑定，首版暂不在 App 对外展示。
5. App 为校园大使补充明确的**团队经营视角**，不再把经营数据藏在深层结果页；「我的团队」应直接呈现当前团队经营概览。

> V1.1 所称「按周」是运营分析维度，不等同于财务结算。首版不新增周结算单、金额核算、对账或打款模型。

## 1. 需求目标

运营方按一期活动，在学校内招募校园大使并发展推广团队。

首版完成五件事：

1. 运营方创建一期「校园大使计划」，向参与学校提供校园大使招募二维码；
2. 学生扫码申请成为校园大使，招募校园推荐官，达到 4 人后点亮身份；
3. 团队点亮后，全员使用各自专属推广码带来新用户注册；
4. 校园大使在 App 查看团队经营情况，运营方在 PC 按周查看团队拉新效果并可导出数据；
5. 运营方继续在 PC 查看全局 / 团队成果并处理团队激励。

本功能属于长期账号上的运营活动身份，不属于某一场赛事身份。每期活动结束后团队自动结束，仅保留历史记录。

## 2. 角色与统一用词

| 对象 | 产品用词 | 说明 |
| --- | --- | --- |
| 活动 | 校园大使计划 | 按期运行，有开始 / 结束时间；属于展示层统一命名 |
| 团队负责人 | 校园大使 | 每个团队只有 1 位；技术内部 role 可继续为 `ambassador` |
| 大使状态 | 待点亮 / 已点亮 | 身份名称不变化，只变化状态 |
| 普通团队成员 | 校园推荐官 | 不获得校园大使身份；技术内部 role 可继续为 `partner` |
| 学校用于招募校园大使的码 | 学校招募码 | 关联「活动 + 学校」，只进入校园大使申请 |
| 校园大使用于组队的码 | 团队招募码 | 只用于邀请校园推荐官加入对应团队 |
| 全员用于拉新的码 | 专属推广码 | 只用于拉新注册归因 |
| 团队内部识别字段 | 团队名 | 后台可指定，未指定自动生成；暂不在 App 对外展示 |
| 原“业绩” | 推广成果 | 学生侧统一采用较友好的表达 |
| 成功拉新指标 | 有效新增 | 新用户完成注册后计数 |
| 周度分析 | 周度团队运营 | 按自然周观察拉新效果，不产生财务结算对象 |
| 运营奖励 | 团队激励 | 发给校园大使，平台不处理团队内部再分配 |

## 3. 整体流程

```text
【PC 运营端】
创建校园大使计划
→ 配置活动时间 / 参与学校

→ 选择已发布活动条款版本
→ 每所学校生成校园大使招募二维码
        ↓
【学生 App】
学生扫码
→ 登录 / 注册
→ 按本期配置填写申请问卷 + 同意本期条款版本
→ 校园大使 · 待点亮
→ 系统创建团队（后台团队名可指定 / 自动兜底）
→ 获得团队招募码
→ 邀请校园推荐官
→ 1 位校园大使 + 至少 3 位校园推荐官
→ 团队点亮
→ 校园大使 · 已点亮
→ 全员获得各自专属推广码
→ 专属推广码 → 下载 App → 新用户注册成功
→ 形成有效新增
        ↓
【学生 App】
校园大使在「我的团队」查看团队经营概览
→ 本周有效新增 / 累计有效新增 / 成员贡献 / 最近拉新
校园推荐官只负责推广，不查看成果数字
        ↓
【PC 运营端】
按周查看活动 / 团队运营效果
→ 查看指定团队详情 / 校园大使申请问卷答案
→ 导出指定团队或全部团队数据
→ 处理团队激励
        ↓
活动结束
→ 团队自动结束
→ 招募码 / 推广码失效
→ 保留历史记录
```

## 4. 学生 App 逻辑

### 4.1 校园大使申请

运营方为参与学校提供对应的校园大使招募二维码。

学生扫码后：

1. 未登录用户先登录或注册，完成后回到申请流程；
2. 按本期活动配置填写校园大使申请问卷；
3. 阅读并同意本期活动绑定的已发布条款版本；
4. 提交成功后直接获得「校园大使 · 待点亮」身份，首版不增加人工审核；
5. 系统创建对应推广团队，并生成该团队的「团队招募码」。

申请问卷由 PC 端按活动配置。首版支持：

- 单行文本；
- 长文本；
- 单选；
- 多选；
- 字段必填 / 非必填；
- 单选、多选的选项配置；
- 后台最小必要预览。

App 应按活动保存的字段结构渲染，不把「自我介绍、校园传播渠道、参与动机」等固定字段写死为永久产品规则。

用户提交申请时，应同时记录其**实际填写的问卷答案**及**实际同意的活动条款版本**，以便运营在团队详情中追溯。

同一用户在同一期活动中只能属于一个推广团队，不能同时成为其它团队的校园大使或校园推荐官。

### 4.2 校园推荐官加入

校园大使分享团队招募码。

- 新用户可注册后加入；
- 已注册老用户也可加入；
- 前提是当前未绑定本期其它推广团队；
- 加入后成为「校园推荐官」；
- 校园推荐官加入团队时不填写校园大使申请问卷；
- 活动期间不可主动退队、不可换队。

团队人数无上限，点亮后仍可继续招募。

### 4.3 团队点亮

点亮条件固定为：

> **1 位校园大使 + 至少 3 位校园推荐官，即团队总人数达到 4 人。**

点亮前：

- 校园大使显示「待点亮」；
- 展示组队进度；
- 只开放团队招募；
- 不开放任何人的专属推广码。

点亮后：

- 校园大使显示「已点亮」；
- 团队进入正式推广状态；
- 校园大使和所有校园推荐官获得各自独立的专属推广码；
- 后续新加入已点亮团队的校园推荐官，也立即获得自己的专属推广码。

### 4.4 专属推广码与有效新增

```text
专属推广码
→ 扫码
→ App 下载流程
→ 安装
→ 新用户完成注册
→ 系统识别推广来源
→ 对应推广人员 +1 有效新增
```

业务口径：

- 从扫码开始必须保留推广来源；
- 每个有效新增能够关联活动、团队和推广人员；
- 仅此前未注册过 App 的新用户注册成功计入有效新增；
- 已注册用户扫码不重复计入；
- 安装归因的具体技术方案由研发确定，本 PRD 不锁定实现方式。

### 4.5 校园大使团队经营视角

V1.0 已存在团队推广成果页，但入口位于「我的团队」深层且受团队状态限制，无法作为校园大使日常经营入口。V1.1 将经营信息前移到「我的团队」主视角。

**校园大使进入「我的团队」后应直接看到：**

- 团队当前状态：待点亮 / 已点亮 / 已结束；
- 团队人数及招募进度；
- **本周有效新增**；
- **累计有效新增**；
- 各校园推荐官的本周贡献；
- 最近有效新增 / 拉新明细；
- 团队招募码（活动进行中且角色为校园大使时）；
- 本人的专属推广码（团队点亮后）。

经营视角首版以「当前周 + 累计」为主，不要求在 App 建设复杂 BI、任意时间范围分析或财务对账。

如保留独立「团队推广成果」详情页，则它应作为经营看板的下钻页，而不是唯一能看到成果的入口。

### 4.6 成果权限

**校园大使可看：**

- 团队人数；
- 本周有效新增；
- 团队有效新增累计；
- 校园大使及各校园推荐官对应的有效新增数量；
- 运营最终确认的必要推广明细。

**校园推荐官可看：**

- 自己已加入的团队；
- 当前活动 / 团队状态；
- 自己的专属推广码。

**校园推荐官不可看：**

- 自己的有效新增数量；
- 其他成员推广成果；
- 团队有效新增总数；
- 团队周度运营数据；
- 排行榜。

### 4.7 活动结束

活动结束后：

- 团队自动结束；
- 团队招募码和专属推广码失效；
- 不再新增推广成果；
- 解除本期团队绑定限制；
- 保留本期身份、团队、申请问卷答案与推广成果记录；
- 校园大使可查看往期团队经营结果；
- 后续新活动可重新申请校园大使或加入新团队。

## 5. PC 运营后台逻辑

校园大使计划应接入**现有 PC 管理端控制面**，不另起一套独立后台。

V1.1 运营心智保持三层，并在活动 / 团队层增加周度运营视角：

```text
活动列表
→ 活动详情（周度团队列表）
→ 团队详情（问卷答案 + 周度运营详情）
```

活动配置与活动条款属于该运营工作台内的配置能力，不新增第二套后台。

### 5.1 活动列表

至少展示：活动名称、时间、状态、覆盖学校数、校园大使数、已点亮团队数、有效新增总数。

活动列表仍看活动整体，不要求在一级列表堆入全部周度分析字段。

### 5.2 创建 / 编辑活动

创建与编辑使用同一套活动配置交互，首版采用现有 PC 公用 Modal，不切换到独立整页表单，也不另造新的弹层体系。

首版配置：

- 活动名称；
- 开始 / 结束时间；
- 参与学校；
- 校园大使申请问卷；
- 活动条款版本。

#### 参与学校

- 使用多选下拉；
- 支持一次选择多所学校；
- 编辑活动时回显已选学校；
- 活动与学校仍保持一对多关系，每所学校独立生成校园大使招募码。

#### 校园大使申请问卷

提供**轻量问卷设计器**，只服务校园大使申请场景，不建设通用低代码表单平台。

支持：

- 新增 / 删除字段；
- 字段上下排序；
- 字段名称；
- 字段类型：单行文本、长文本、单选、多选；
- 必填 / 非必填；
- 单选、多选的选项配置；
- 最小必要预览。

保存后，学生 App 按该结构渲染本期申请问卷。

团队点亮门槛首版固定为「1 位校园大使 + 3 位校园推荐官」，不做复杂规则配置器。

### 5.3 活动条款库与版本规则

活动条款不作为活动表单中的一段临时文本维护，而作为运营工作台中的独立版本化内容管理。

首版规则：

- 每份条款有稳定 ID 和面向运营可读的版本号；
- 条款存在「草稿 / 已发布」状态；
- 运营可使用富文本编辑草稿；
- 已发布版本不可直接覆盖修改；
- 如需修改，必须从旧版本复制或新建新版本，再次发布；
- 创建 / 编辑活动时只能选择**已发布版本**，不要求运营手填技术 ID；
- 活动开始后，当期绑定的条款版本锁定，不随条款库后续版本变化；
- 学生申请记录保存其实际同意的条款版本。

首版正式发布版本沿用：

> **《校园大使计划活动条款》v1.0**

活动名称与条款标题都属于展示层，统一使用「校园大使计划 / 校园大使计划活动条款」；技术内部命名和历史稳定 ID 不随展示文案迁移。

正文至少覆盖：

1. 参与资格与校园大使 / 校园推荐官身份说明；
2. 同一期活动中同一用户只能属于一个团队；
3. 活动期间不可主动退队或换队；
4. 团队点亮条件与点亮前后权限；
5. 团队招募码、专属推广码的用途边界；
6. 有效新增的计算口径；
7. 活动结束后的团队、招募码、推广码处理；
8. 推广成果与团队激励说明；
9. 为完成申请、组队、推广归因与成果统计所需的必要数据使用说明。

### 5.4 学校与校园大使招募码

- 每所学校生成独立的校园大使招募二维码；
- 二维码关联「活动 + 学校」；
- 二维码必须进入对应学校的**校园大使申请链路**，不得进入团队加入链路；
- 二维码卡片应包含适度的活动 / 学校识别信息，不使用纯通用占位块；
- 支持点击二维码卡片查看大图；
- 大图在 Modal 中展示，并支持下载；
- 可查看该学校产生的校园大使、团队与推广数据。

### 5.5 团队名与团队招募码

每个推广团队增加内部「团队名」字段：

- 团队名属于团队本身，并与该团队的团队招募码绑定；
- 运营可在后台指定 / 修改团队名；
- 未指定时系统自动生成可读且唯一的兜底名称；
- 自动生成格式不作为业务强约束，但必须能稳定区分团队；
- 团队名可用于后台列表、详情、筛选和导出；
- **首版暂不在 App 用户侧展示团队名**；
- 团队名不是新的团队身份或层级，不影响 teamId、组队、点亮与归因逻辑。

### 5.6 活动详情｜周度团队列表

活动详情顶部继续展示活动整体数据：覆盖学校、校园大使、已点亮团队、校园推荐官、累计有效新增。

团队列表增加周度运营视角：

- 默认查看**当前自然周（周一 00:00 ～ 周日 23:59）**；
- 可切换查看其它周；
- 支持全部团队与基础状态筛选；
- 每个团队至少展示：
  - 团队名（内部）；
  - 校园大使；
  - 学校；
  - 团队状态；
  - 团队人数；
  - 本周有效新增；
  - 累计有效新增；
  - 团队激励状态。

周度视角只是对既有 `registeredAt` 拉新事实的聚合，不创建第二套推广成果真相源。

### 5.7 团队详情｜申请问卷答案视角

团队详情必须补充清晰的「校园大使申请问卷」区域，而不是只把少量字段平铺在页面上。

展示要求：

- 校园大使基本信息；
- 该团队所属活动、学校和内部团队名；
- 按申请问卷原顺序展示**题目 + 答案**；
- 单选 / 多选答案按可读文本展示；
- 非必填且未填写的题目明确显示「未填写」；
- 同时展示申请时间及实际同意的条款版本；
- 校园推荐官不产生第二份申请问卷答案。

运营在团队详情查看的是该校园大使真实提交记录，不允许因为后续调整问卷配置而覆盖历史答案。

### 5.8 团队详情｜周度运营效果

在同一团队详情中提供按周查看能力：

- 当前所选周有效新增；
- 累计有效新增；
- 按成员拆分本周贡献；
- 本周每日新增分布 / 简单趋势；
- 本周有效新增明细；
- 可切换其它自然周查看历史。

首版以可读列表 / 简单趋势为主，不建设复杂 BI 系统。

### 5.9 数据导出

运营方可在当前活动和所选周范围内导出团队推广数据。

至少支持两种范围：

1. **指定团队**：导出当前选中的一个团队；
2. **全部团队**：导出当前活动下全部团队。

导出至少包含：

- 活动；
- 周区间；
- 团队 ID；
- 团队名；
- 学校；
- 校园大使；
- 团队状态；
- 团队人数；
- 本周有效新增；
- 累计有效新增；
- 成员及成员本周有效新增。

如导出明细级数据，应继续保留推广人员、有效新增账号 / 记录 ID、注册时间等已有归因事实。

导出属于运营数据能力，不自动产生财务结算、账单或打款记录。

### 5.10 团队激励

平台首版只负责：

- 提供团队推广成果；
- 识别对应校园大使；
- 如业务需要，记录简单的「未处理 / 已处理」状态。

平台不计算团队内部个人分成，不给校园推荐官逐人结算，也不干预校园大使如何分配激励。

## 7. 首版不复杂化

- 不做多级代理、上下级校园大使或子团队；
- 不做校园推荐官排行榜；
- 不做活动期间退队 / 换队；
- 不做永久校园大使等级；
- 不把周度运营视角扩展成真实财务周结算、账单、对账与打款系统；
- 不做真实财务结算与个人分账；
- 不把推广成果混入赛事成绩 / 赛事身份；
- 不建设通用低代码表单平台；
- 不为校园推荐官再建第二套申请问卷；
- 不建设复杂条款审批流；
- 团队名不形成新的组织层级或用户侧品牌体系；
- 不新建与现有账号、学校、PC 控制面冲突的第二真相源。

## 9. 原型操作说明

本节用于产品评审、运营演示和人工验收。描述的是中保真原型中**如何把完整业务链实际走一遍**。V1.0 已完成的路径仍可使用；V1.1 新增项施工完成后应按本节新增检查点验收。

### 9.1 演示前准备

建议同时打开：

- PC 运营管理端；
- Mobile 原型窗口。

如需验证 PC / Mobile 同一业务状态，优先从 PC「校园大使计划」工作台进入**中保真联动预演**，由 PC 打开对应 Mobile 预演窗口。该模式用于原型跨端验收，不代表生产环境的数据同步方式。

活动状态按开始时间 / 结束时间自动判断：

- 未到开始时间：未开始；
- 时间区间内：进行中；
- 超过结束时间：已结束。

因此人工验收申请、组队和推广时，应使用处于「进行中」的活动。

### 9.2 PC：创建一期校园大使计划

1. 进入 PC 管理端「校园大使计划」；
2. 点击「创建活动」；
3. 在公用 Modal 中填写：
   - 活动名称；
   - 开始 / 结束时间；
   - 参与学校；
   - 校园大使申请问卷；
   - 已发布活动条款版本；
4. 「参与学校」可一次选择多所学校；
5. 在问卷设计器中可新增、删除、排序字段，并设置单行文本、长文本、单选、多选及必填状态；
6. 保存活动后进入活动详情。

如需演示条款版本管理，可先进入活动条款维护入口：

```text
已发布版本
→ 从旧版本创建草稿 / 新建版本
→ 编辑正文
→ 发布
→ 新活动选择该已发布版本
```

已发布版本不直接覆盖修改。

### 9.3 PC：获取学校校园大使招募二维码

1. 在活动详情找到对应学校的招募二维码；
2. 点击二维码卡片，可打开大图 Modal；
3. 可下载二维码用于演示或线下物料；
4. 每所学校二维码独立，扫码后应直接进入该活动、该学校的校园大使申请流程。

注意：**学校招募码只用于申请校园大使，不用于加入推广团队。**

### 9.4 App：模拟学生扫描学校招募码

当前原型不要求真实摄像头扫码。人工验收时：

1. 打开 Mobile「我的」；
2. 点击资料卡上的通用扫一扫入口；
3. 打开「扫一扫 · 原型模拟」；
4. 选择一个用于本次演示的学生账号；
5. 选择「学校招募码」并扫描当前活动对应学校的码；
6. 系统应直接进入校园大使申请页，不经过“选择申请大使还是加入团队”的混合页面。

「扫一扫 · 原型模拟」是人工验收工具，不属于正式用户功能。

### 9.5 App：提交校园大使申请

在申请页：

1. 确认活动与学校信息；
2. 按 PC 当前活动配置填写申请问卷；
3. 点击「校园大使计划活动条款」标题，查看正式条款正文；
4. 返回申请页，勾选同意条款；
5. 提交申请。

提交成功后应观察到：

- 当前账号成为「校园大使 · 待点亮」；
- 「我的」资料卡出现灰色「校园大使」身份标识；
- 「我的」服务区出现「我的团队」入口；
- 进入「我的团队」后可看到组队进度与真实团队招募二维码；
- PC 团队详情可查看该校园大使完整的申请问卷答案；
- PC 可看到该团队的内部团队名；未指定时已有自动生成的兜底名称。

### 9.6 App：招募 3 位校园推荐官并点亮团队

1. 以校园大使身份进入「我的团队」；
2. 点击团队招募二维码可查看大图，并可长按保存 / 下载；
3. 再次使用「扫一扫 · 原型模拟」切换为第 1 位校园推荐官；
4. 选择「团队招募码」；
5. 扫描该校园大使的团队招募码；
6. 在邀请确认页确认：邀请人、活动、学校、加入身份「校园推荐官」及活动期间不可退队 / 换队；
7. 点击「确认加入」；
8. 依次切换第 2、3 位校园推荐官重复以上步骤。

当第 3 位校园推荐官加入后，团队达到：

> 1 位校园大使 + 3 位校园推荐官

此时应自动点亮，无需运营手工审批。

点亮后检查：

- 校园大使状态变为「已点亮」；
- 校园大使获得个人专属推广码；
- 3 位校园推荐官分别获得自己的专属推广码；
- 校园推荐官视角看不到团队有效新增、其他成员成果、周度运营数据或排行榜。

### 9.7 App：验证点亮后仍可继续招募

为验证“4 人只是最低门槛，不是人数上限”：

1. 切换第 4 位校园推荐官；
2. 再次扫描同一团队招募码；
3. 确认加入；
4. 新成员加入后应立即获得自己的专属推广码；
5. 团队继续保持已点亮状态。

### 9.8 App：模拟专属推广码带来有效新增

1. 选择任意一位已获得专属推广码的成员；
2. 展示 / 打开其个人专属推广二维码；
3. 在通用扫一扫原型模拟中选择「专属推广码」；
4. 使用一个此前未注册过 App 的测试用户完成注册模拟；
5. 注册成功后，该有效新增应归因到对应活动、团队和推广人员。

重复扫码或使用已注册账号，不应重复增加有效新增。

### 9.9 App：检查校园大使经营视角与权限

以校园大使身份进入「我的团队」，**无需先寻找深层“结果页”**，主页面即可看到经营概览：

- 团队人数 / 招募进度；
- 本周有效新增；
- 累计有效新增；
- 校园推荐官本周贡献；
- 最近有效新增 / 拉新明细。

如进入独立「团队推广成果」详情页，可进一步查看成员成果与完整明细。

再切换任意校园推荐官：

- 可看自己所属团队与当前活动状态；
- 可看自己的专属推广码；
- 不应看到自己的有效新增数量；
- 不应看到团队总新增；
- 不应看到周度运营数据；
- 不应看到其他成员成果或成员级明细。

### 9.10 PC：检查申请问卷、周度运营与导出

完成 App 申请、组队、点亮和有效新增后，返回 PC：

1. 打开同一期活动详情；
2. 选择当前自然周，核对团队列表中的本周有效新增与累计有效新增；
3. 切换其它周，确认统计随 `registeredAt` 所属周变化；
4. 进入对应团队详情；
5. 核对团队内部名称、校园大使、学校、团队状态与成员；
6. 打开「校园大使申请问卷」，逐题核对 App 提交的真实答案；
7. 查看本周成员贡献、每日新增 / 简单趋势与拉新明细；
8. 分别验证：
   - 导出指定团队；
   - 导出全部团队；
9. 如本期启用团队激励状态，可将该团队从「未处理」更新为「已处理」。

周度视角只用于运营效果分析，不产生周结算账单。激励仍只记录到校园大使对应团队，不在原型中给校园推荐官逐人分账。

### 9.11 验证活动结束与历史保留

活动结束状态由结束时间自动生效。使用已结束活动或把验收活动配置到可形成结束态的时间范围后，检查：

- 学校招募码明确提示活动已结束 / 不可申请；
- 团队招募码不可继续加入；
- 专属推广码不可继续形成有效新增；
- 团队状态转为历史 / 已结束；
- 已有申请问卷答案、成员、推广成果和激励状态仍保留；
- 校园大使仍可查看往期经营结果；
- 旧团队不再阻止同一账号参加下一期校园大使计划。

### 9.12 推荐完整演示顺序

一次完整产品评审建议按以下顺序连续演示：

```text
PC 创建活动
→ 配置学校 / 校园大使申请问卷 / 已发布条款
→ 查看学校招募二维码
→ 开启中保真联动预演
→ App 扫学校码
→ 提交校园大使申请
→ PC 查看团队内部名称 + 完整问卷答案
→ App 我的：灰色校园大使标识 + 我的团队
→ 展示团队招募二维码
→ 3 位校园推荐官依次扫码加入
→ 团队自动点亮
→ 第 4 位校园推荐官继续加入
→ 展示全员个人专属推广码
→ 新用户通过其中一个推广码完成注册模拟
→ 校园大使在「我的团队」直接查看经营概览
→ 切换校园推荐官验证成果数字隔离
→ PC 按周查看团队列表 / 团队详情
→ 导出指定团队 / 全部团队
→ 处理团队激励
→ 验证活动结束、二维码失效、历史保留与下一期可重新参加
```

### 9.13 原型模拟能力边界

以下能力仅用于中保真验收，不应被研发理解为正式产品需求：

- 「扫一扫 · 原型模拟」中的账号切换；
- 预置的多位校园推荐官测试身份；
- PC「中保真联动预演」窗口与跨窗口 demo state 同步；
- 前端模拟新用户注册及有效新增归因。

正式实现时应替换为真实登录账号、真实扫码 / Deep Link、服务端活动与团队状态、安装 / 注册归因、后台周度聚合与正式数据导出，但业务规则与权限边界保持本 PRD 定义不变。
