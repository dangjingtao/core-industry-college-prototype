## 1. 原型落地目标

T038 保留两类广告场景：

1. 免费福利领取前的激励广告；
2. 权益详情页底部的信息流广告。

广告只承担“行为条件”与广告展示职责，不重新定义权益库存、订单或真实发券系统。

## 2. 广告位 A：福利领取前激励广告

### 当前原型位置

- 免费福利「领取」按钮点击后；
- 使用 `RewardedVideoAd` 模拟全屏激励视频；
- 带「广告」标识、倒计时、进度条与跳过能力。

### 2026-08-26 产品评审后应采用的业务流程

```text
点击领取
→ 提示需完成激励广告条件
→ 播放广告
→ 广告完成
→ 发起福利领取 / 发放请求
→ 发放成功：显示领取成功
→ 发放失败：显示失败原因，并允许按业务规则重试
```

必须区分三个状态：

- 广告完成；
- 福利领取请求处理中；
- 福利领取成功 / 失败。

**广告播放完成不能直接等同于卡券已经发放成功。**

原型阶段可以继续模拟发放结果，但交互和状态命名必须按上述结构设计，为后续真实权益 API 留出失败、库存不足、超时、重复领取等状态。

### 跳过规则

- 跳过激励广告 = 本次领取条件未完成；
- 不得显示“领取成功”；
- 用户可以返回权益详情并重新发起领取。

## 3. 广告位 B：权益详情页信息流

- 位置：权益详情页底部；
- 形式：信息流广告卡片；
- 必须带明确「广告」标识；
- 可有广告主与 CTA；
- 不影响权益本身的领取状态与排序事实。

## 4. 当前实现文件

- 广告组件：`apps/mobile/src/features/long-term-assets/Ads.tsx`
- 权益详情页：`apps/mobile/src/features/long-term-assets/BenefitsPages.tsx`
- 权益数据：`apps/mobile/src/features/long-term-assets/data.ts`

当前已有：

- `RewardedVideoAd`；
- `InfoFeedAdCard`；
- `useInfoFeedAd(seed)`；
- 免费福利领取前激励广告动线；
- 非 API 接入权益的外部合作方领取入口。

## 5. 关于当前“API 直接发放”原型

现有原型曾把部分打车 / 外卖券从外部 H5 跳转改为“API 接口直接发放”，并新增 `apiIssued` / `useInApp` 等字段。

该实现只能视为**权益发放能力的原型模拟**。真实产品边界仍服从 T035 与 19 号 PRD：

- T038 不负责定义真实订单 / 库存 / 发券系统；
- 若后续接入真实 Provider API，应由权益领域承接发放事实；
- T038 只消费发放结果并正确展示成功 / 失败状态。
