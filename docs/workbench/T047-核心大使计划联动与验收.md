# T047｜核心大使计划 PC 运营配置与招募素材收口

## 1. 目标

把 PC「核心大使计划」从可演示页面收口为可由运营人员自然配置的中保真工作台，并为 App 扫码申请提供可消费的活动配置与招募素材。

本卡只处理 PC 运营配置与学校招募素材，不提前施工 App 扫码分流和最终生命周期联动。

## 2. 施工范围

### A｜创建活动统一交互

- 「创建活动」不再切换成独立整页表单；
- 统一使用 PC 现有公用 Modal 组件；
- 编辑活动沿用同一套编辑容器与字段规范；
- 不另造新的弹层体系。

### B｜参与学校改为多选下拉

- 「参与学校」由 checkbox 平铺改为多选下拉；
- 支持多学校选择、已选项回显和编辑；
- 不改变活动按学校生成学校招募码的业务关系。

### C｜申请表字段升级为轻量表单设计器

不做通用低代码表单平台，只做本业务需要的轻量配置：

- 字段新增 / 删除 / 排序；
- 字段名称；
- 字段类型：单行文本、长文本、单选、多选；
- 是否必填；
- 单选 / 多选的选项配置；
- 最小必要预览；
- 保存后 App 大使申请页可按该配置渲染。

禁止继续使用「自我介绍、校园传播渠道、参与动机」这种顿号字符串作为正式配置方式。

### D｜活动条款库与首版正式条款

补齐「核心大使计划活动条款」真实正文，并建立轻量版本机制：

- 条款在独立维护入口中使用富文本编辑；
- 条款有稳定 ID 与可读版本号；
- 已发布版本不可直接覆盖修改；
- 修改需从旧版本复制 / 新建新版本后再次发布；
- 活动创建只允许选择已发布版本，不手填技术 ID；
- 活动开始后保留当期绑定版本；
- App 申请提交需记录用户实际同意的条款版本。

首版条款至少覆盖：参与资格与身份、同一期单团队约束、活动期间不可退队/换队、团队点亮、推广码与有效新增口径、活动结束、推广成果与团队激励、必要数据使用说明。

### E｜学校招募二维码素材化

- 活动详情继续按学校展示学校招募二维码；
- 二维码卡片支持点击打开 Modal 大图；
- Modal 内支持下载；
- 展示应带适度活动 / 学校识别色彩，不做纯通用占位块；
- payload 仍必须明确进入对应学校的大使申请链路，不得指向团队加入链路。

## 3. 明确不做

- 不在本卡实现 App 扫码器码型分流；
- 不在本卡实现大使个人身份入口；
- 不在本卡处理活动结束后的团队 / 推广码生命周期；
- 不建设通用表单 SaaS 或复杂审批流。
