## 1. 目标

把 App 与 PC 运营工作台串成一条完整业务链，并验证状态、权限和活动生命周期一致。

## 2. 必验场景

### A｜申请与点亮

```text
PC 创建活动 + 学校招募码
→ 学生扫码申请核心大使
→ App 显示待点亮
→ PC 出现该大使团队
→ 3 名推广伙伴加入
→ 团队自动点亮
→ App 大使已点亮
→ PC 团队进入推广状态
```

### B｜点亮后继续扩张

```text
团队已点亮
→ 大使继续邀请推广伙伴
→ 新成员加入
→ 团队人数继续增加
→ 新成员获得专属推广码
```

### C｜有效新增与权限

```text
推广伙伴专属推广码
→ 新用户注册成功
→ 对应推广人员 +1 有效新增
→ 大使端团队成果同步变化
→ PC 活动 / 团队数据同步变化
→ 推广伙伴本人仍看不到成果数字
```

### D｜活动结束

```text
活动到期 / 结束
→ 团队自动结束
→ 团队招募码失效
→ 专属推广码失效
→ 不再产生新推广成果
→ 历史团队 / 成果仍可查看
→ 用户可在后续活动重新参加
```

## 3. 工程验收

- [ ] App 与 PC 均可正常 build；
- [ ] 新增路由 / 入口无明显死链；
- [ ] App 与 PC 对活动、团队、有效新增使用同一业务真相源；
- [ ] 核心大使可看团队成果，推广伙伴不可看；
- [ ] 活动结束后二维码、团队关系和历史记录正确收口；
- [ ] 不破坏现有参赛、就业 / 实习等母动线；
- [ ] 补最小必要的浏览器 / E2E 证据，不以“页面画完”代替业务验收。

## 4. 本轮完成定义

现场可连续演示：

> 运营建活动并发学校招募码 → 学生成为核心大使 → 招募 3 名推广伙伴 → 团队点亮 → 全员推广 → 大使看团队推广成果 → 运营查看并处理团队激励 → 活动结束后保留历史记录。
