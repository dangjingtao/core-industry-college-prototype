## 1. 目标

在 T047、T048 完成 PC 配置和 App 扫码体验后，把 PC 与 App 串成一条可连续演示、状态一致、生命周期完整的核心大使业务链，并完成最终回归。

本卡不再扩展新的业务功能，只负责跨端真相源、生命周期、边界错误和最终验收。

## 2. 完整业务链

最终可连续演示：

```text
PC 创建活动 / 选择学校 / 配置申请表 / 绑定已发布条款
→ 生成学校招募二维码
→ 学生从 App 通用扫码器扫描学校码
→ 填写申请表 + 阅读并同意条款
→ 成为「核心大使 · 待点亮」
→ App 我的页出现灰色核心大使标识 + 我的团队
→ 核心大使展示团队招募二维码
→ 3 位推广伙伴扫码确认加入
→ 团队自动点亮
→ 大使 + 全部推广伙伴获得专属推广码
→ 团队继续邀请第 4 位及后续伙伴
→ 新成员立即获得专属推广码
→ 新用户通过个人推广码注册
→ 形成有效新增并归因到具体推广人员
→ 核心大使查看团队推广成果
→ 推广伙伴仍看不到成果数字
→ PC 查看活动 / 团队 / 成员 / 有效新增并处理团队激励
→ 活动结束
→ 招募与推广停止，历史保留
→ 后续新活动允许用户重新参加
```

## 3. App / PC 同一业务真相

中保真阶段不建设生产后端，但演示时 PC 与 App 必须观察到同一份核心大使业务状态。

最终实现：

- PC 创建 / 编辑的活动配置可被 App 消费；
- App 产生的大使、伙伴、点亮状态能在 PC 看到；
- App 产生的有效新增能在大使结果页和 PC 同步体现；
- PC 处理团队激励后状态可持续展示；
- 不再通过两份互不相干的 seed / React 内存态假装“前后台已联动”。

实现采用中保真共享 demo state：PC / Mobile 各自持久化，PC 打开 Mobile 联动预演窗口后通过受限 origin 的 `postMessage` 握手同步同一份业务状态；Mobile 后续产生的申请、组队、点亮与有效新增会回传 PC。该桥接只用于中保真联动演示，不冒充生产后端。

## 4. 活动生命周期

### 活动开始

- 维持“按 startsAt / endsAt 自动判断未开始、进行中、已结束”的规则；
- 是否增加手动发布 / 开始动作属于独立产品决策，不在本卡增加；
- 未开始活动的学校招募码不可形成有效申请。

### 活动结束

到期后按有效状态统一收口：

- 团队逻辑状态视为已结束；
- 学校招募码失效；
- 团队招募码失效；
- 专属推广码失效；
- 不再产生新有效新增；
- 已存在成员、团队、推广成果、申请信息、激励状态作为历史保留；
- 结束后的旧团队不阻止同一账号参加后续新活动。

实现统一以活动有效状态派生团队结束状态，并在扫码、申请、入队、团队页、推广注册等入口使用同一生命周期判断。

## 5. 已知边界问题收口

### A｜过期推广码页面卡死

已实现：

- 页面进入时根据活动有效状态判断；
- 已过期明确显示“活动已结束 / 推广码已失效”；
- 注册模拟动作返回明确结果，不再留下 pending 按钮永久禁用状态。

### B｜同活动其他团队成员模拟为“新用户”

共享动作与页面统一区分：有效新增、重复新增、已注册、本期团队成员、活动/码失效。被拒绝后恢复可操作状态，不重复计数。

### C｜历史团队阻塞未来活动

- “同一用户同一期只能属于一个团队”只在 campaign 范围内生效；
- 我的页优先选择当前进行中团队，其次未开始团队，最后才展示往期记录；
- 已结束团队不会阻止同一账号参加后续 campaign。

### D｜非本人 / 未登录团队信息暴露

- 团队页和成果页增加登录门禁；
- 非本团队成员直输路由只能看到无权提示，不暴露成员、招募码与成果；
- 推广伙伴仍只看团队/活动状态和自己的个人推广码，不看成果数字及其他成员明细。

### E｜未开始 / 已结束码的用户反馈

学校码、团队码、推广码在未开始 / 已结束场景直接给明确状态，不再进入错误表单后静默失败。

### F｜T048 回归补收口

T049 施工复核额外发现并修复两项真实回归：

1. `/me` 通用扫码入口在 T048 接入大使码型后丢失原有福利 / 兑换码模拟链路；T049 已恢复福利兑换码分流，确保通用扫码器不是“大使专用扫码器”。
2. 已属于本期团队的推广伙伴再次扫描学校招募码时仍可进入并提交大使申请；T049 已在申请页增加同 campaign 团队身份守卫，只允许查看当前团队，禁止二次申请或换队。
