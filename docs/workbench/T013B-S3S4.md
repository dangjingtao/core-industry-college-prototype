## 一、S3｜平台 / 内容运营｜Mockplus 108–113

### 动态答题

以 Mockplus“平台运营目标点选”为基线：

- [ ] 动态问答逐题呈现。
- [ ] 选择主要发布平台，例如抖音 / 小红书 / 微信视频号。
- [ ] 选择本次内容运营目标，例如品牌认知 / 销售转化 / 搜索权重 / 用户评价。
- [ ] 保留 AI 根据回答准备下一题的反馈。
- [ ] 保留作答完善度、补充说明等共用 Pattern。

### 文案生成确认｜Mockplus 109

- [ ] 任务目标明确表达：根据需求、运营平台、商品 / 项目信息生成话术、文案等。
- [ ] 展示问答摘要、AI 提取核心信息与主观补充。
- [ ] 展示预计算力 / 冻结提示。
- [ ] 支持确认生成 / 返回修改。
- [ ] 团队型技能继续遵守：结果全队可见、队员可编辑后提交确认、队长可采纳或标记用于比赛。

### 图片 / 视频生成确认｜Mockplus 110

S3 在原型中不是只有一条文案成果链，必须保留第二种生成形态：

- [ ] “图片 / 视频内容生成”作为独立生成确认页面 / 状态。
- [ ] 基于内容方案与上传商品图等信息生成图片 / 视频的 mock 流程。
- [ ] 原型阶段不伪造真实图片生成服务；允许使用明确占位素材。

### 任务进度｜Mockplus 111

复用 T013A 的同一进度 Pattern：

- [ ] 显示正在生成具体内容，例如“小红书种草图文”。
- [ ] 显示冻结算力、读取参赛档案、检查问答材料、生成中、质量检查。
- [ ] 可离开，完成后站内消息通知。
- [ ] 原型允许“模拟完成”。

### 文案成果｜Mockplus 112

成果详情按 Mockplus 内容素材卡实现，至少包含：

- [ ] 标题。
- [ ] 详情页文案。
- [ ] 短视频脚本。
- [ ] 直播脚本 / 话术。
- [ ] 客服话术。
- [ ] 编辑 / 分享 / 队长提交确认。

### 图片 / 视频成果｜Mockplus 113

- [ ] 图片素材区域。
- [ ] 视频素材区域。
- [ ] 保留内容素材卡与编辑 / 分享 / 提交确认 Pattern。
- [ ] 图片 / 视频为原型示例成果，不冒充真实生成结果。

**注意：我此前写过“保存版本 / 版本对比 / 采用版本”，但 Mockplus 108–113 没有把它设计成明确交互，因此从本卡 P0 验收中移除。**

## 二、S4｜数据复盘｜Mockplus 123–126

### 动态答题｜Mockplus 123

以“经营周报分析”为基线：

- [ ] 动态问答逐题呈现。
- [ ] 选择最关注的经营指标，例如 GMV / 销售额、订单量与客单价、流量与转化率。
- [ ] 选择周报重点，例如同比 / 环比趋势、异常波动预警、渠道对比等。
- [ ] 保留 AI 动态准备下一题、完善度、补充说明等 Pattern。

**不要因为六阶段概念描述里提过 Excel / 截图，就自行把“上传 Excel”变成 S4 唯一主入口。若 Mockplus 具体页没有要求在该步骤上传，则按页面事实施工；需要数据上传时沿用共用上传 Pattern。**

### 生成确认｜Mockplus 124

- [ ] 展示问答摘要、AI 提取核心信息、主观补充。
- [ ] 展示作答完善度。
- [ ] 展示预计算力 / 冻结提示。
- [ ] 支持确认生成 / 返回修改。
- [ ] 结果对全队可见，角色边界与 S1–S3 一致。

### 任务进度｜Mockplus 125

复用同一 Task Runtime / 进度页面 Pattern，不增加 S4 独立状态机。

### 成果详情｜Mockplus 126

以“经营周报分析小报告”为基线：

- [ ] 核心发现 / 关键结论。
- [ ] 薄弱环节。
- [ ] 优先行动清单。
- [ ] 详细分析。
- [ ] 报告评级与多维评估。
- [ ] 编辑 / 分享 / 队长提交确认。

不得把桌面数据看板硬缩放进手机页；但也不得脱离 Mockplus 现有报告结构自行重做一套数据中心。

- 不伪造真实平台发布、真实数据解析或真实图片生成。
- 不把非 Mockplus 的版本管理当成阻断验收项。
- 不改变 T013A 共用 Runtime 边界；确有缺口先记录再统一修复。
