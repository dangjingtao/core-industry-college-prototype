# T013B｜创赛工坊 S3 内容代运营 + S4 数据复盘

**类型：施工卡**  
**状态：待执行**  
**优先级：P0**  
**前置：T013A**

## 目标

在 T013A 已建立的创赛工坊首页、技能详情、Task Runtime、任务进度、历史成果与算力展示上，完成 S3 / S4 两个运营阶段技能包。不得复制新的工坊壳、历史记录或运行状态模型。

## 一、S3｜内容代运营包 · 跑运营

### 采集

- [ ] 平台 / 目标点选。
- [ ] 卖点排序。
- [ ] 风格量表。
- [ ] 商品 / 项目信息确认。
- [ ] 运营成员完成结构化采集，队长最终确认生成。

### 产出

- [ ] OPC 内容方案：标题、详情、脚本、话术、配图建议。
- [ ] 成果按内容块展示，不把整份结果塞成单一长文本。
- [ ] 每个内容块支持修改、采用、放弃。
- [ ] 建立 S3 成果版本能力：保存版本、版本对比、选择采用版本。
- [ ] 已采用内容回流当前赛事项目的展示 / 工作材料层，不复制项目主档真相源。

## 二、S4｜数据复盘包 · 看数据

### 采集

- [ ] 上传 Excel / 截图入口；原型阶段允许 mock 上传。
- [ ] 指标勾选。
- [ ] 异常点选。
- [ ] 下期目标设定。
- [ ] 数据成员上传 / 填写，队长确认后启动生成。

### 产出

- [ ] OPC 经营周报：核心指标、漏斗、异常、用户画像、建议。
- [ ] 手机端成果使用适合移动端阅读的图表 / 指标卡 / 异常卡，而不是桌面报表硬缩放。
- [ ] 回流下期验证指标与行动建议。
- [ ] 不伪造 Excel 解析、OCR 或真实经营数据分析能力；mock 数据必须可识别为原型数据。

## 共用 Runtime 要求

- S3 / S4 必须直接使用 T013A 的任务状态、进度页、成果页 Pattern、历史成果与算力明细。
- 运行中离开 / 返回、失败 / 重试、完成后查看历史的行为必须与 S1 / S2 一致。
- 所有任务继续带当前 `competitionId` / workspace context，历史成果不允许跨赛事串线。

## 验收动线

```text
赛事工作区 → 创赛工坊

S3：
→ 内容代运营
→ 平台 / 目标 / 卖点 / 风格 / 商品信息
→ 队长确认
→ 运行中
→ 内容方案
→ 分块修改
→ 保存版本 / 对比 / 采用

S4：
→ 数据复盘
→ 上传数据 → 指标 / 异常 / 目标
→ 队长确认
→ 运行中
→ 经营周报
→ 下期验证指标
```

## 禁止

- 不为 S3 单独做一套“内容 AI 聊天”。
- 不为 S4 建独立数据中心或第二份项目经营数据真相源。
- 不伪造真实平台发布、真实 Excel 分析或真实图片生成。
- 不绕过队长确认直接消耗算力占位。
- 不改变 T013A 已冻结的共用 Runtime 契约，若确有缺口先记录并在底座统一修复。
