# T018｜应用中心（tabbar 第 5 入口 + 分组宫格聚合页）

**类型：施工卡**  
**状态：待执行**
**优先级：P1**

## 背景

当前手机端 tabbar 为 4 项：

```text
首页 /home │ 赛事 /competitions │ 机会 /opportunities │ 我的 /me
```

平台支撑型能力（课程、权益、可信成果、任务中心、赛友内容、快速验真、公告、客服等）入口分散：

- 首页有「成长资源」5 宫格 + 任务专区；
- 「我的」页有「服务入口」列表；
- 部分功能藏在二级 / 三级页面（兑换中心、我的卡券、成长概览、快速验真、投递记录、我的比赛团队、公告资讯），用户需要时难以快速找回。

产品总纲（`docs/product/00-product-master-context.md`）已明确：*"课程很重要""可信成果很重要"都不自动等于它们必须占底部一级导航*，且不要大量能力平铺。支撑能力应增强「参赛 / 就业」两条主线，而不是抢一级导航主叙事——但它们仍需要一个稳定的全量出口。

## 产品定义（2026-08-19 与需求方确认）

> **应用中心 = 平台「功能工具」的全量出口。** 凡是不属于参赛 / 就业主线、但用户需要时应能翻到的功能，都收进这里，用分组宫格承载。它不做成「小程序 / 应用商店」式市场，而是类似支付宝服务页的分组功能入口。

设计原则：

1. **定位明确**：主线（参赛 / 就业）继续占一级导航；应用中心只收工具性、内容性、福利性功能。
2. **真实跳转**：每个入口都跳现有真实路由，不造假按钮、不新建第二套页面。
3. **全量聚合，不改现状**：首页 5 宫格、我的页服务入口原样保留；应用中心做全量集，允许短期存在重复入口，后续可再清理（本卡不做入口去重改造）。
4. **扩展性好**：分组结构便于后续新增模块（如创域 / 线下运营解冻后）直接加入。

## 目标

- tabbar 从 4 项扩展为 5 项：首页 / 赛事 / 机会 / **应用中心** / 我的；
- 新增 `/apps` 分组宫格页，作为支撑功能的统一快速入口；
- 把目前藏得深的入口（兑换中心、我的卡券、成长概览、快速验真、投递记录、我的比赛团队、公告资讯等）显性化。

## 禁止

- 不把应用中心设计成「小程序 / 应用商店」形态（无第三方应用、无安装 / 卸载语义）。
- 不为应用中心新建任何业务真相源（无新 store、无新状态模型）；页面只做入口聚合跳转。
- 不修改首页「成长资源」宫格与「我的」服务入口（本卡不做去重改造）。
- 不把赛事 / 机会等主线入口迁入应用中心。
- 不为应用中心恢复 D03 旧任务列表、D08 主体管理等冻结功能。

## 验收动线

```text
任意 tab 进入
→ 应用中心（/apps）
→ 分组宫格浏览
→ 点击任一入口 → 到达对应真实页面 → 返回应用中心

深度链接：直接访问 /apps 刷新不 404
未登录：/apps 可浏览，需登录入口引导登录 returnTo /apps
```
