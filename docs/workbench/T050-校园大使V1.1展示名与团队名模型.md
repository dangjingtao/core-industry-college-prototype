## 1. 目标

为 V1.1 提供统一地基：完成校园大使计划所有用户可见 / 运营可见身份名称调整，并给团队增加后台可识别的团队名。

本卡只处理共享语义和团队名，不提前施工 PC 周运营、问卷答案详情或 App 经营看板。

## 2. 展示名统一

所有产品展示统一使用：

- `核心大使` → **校园大使**；
- `推广伙伴` → **校园推荐官**。

覆盖范围至少包括：

- Mobile 页面标题、身份标签、状态说明、按钮、扫码文案、空态 / 错误提示；
- PC 活动列表、团队列表、团队详情、申请信息、成员身份、运营说明；
- 二维码卡片 / Modal / 下载文件名中的用户可见语义；
- 活动条款正式正文；
- 导出文件中的身份展示字段；
- 新增测试用例中面向产品的断言文案。

### 不改

- `AmbassadorMemberRole = "ambassador" | "partner"`；
- 既有类型、函数、文件、路由中的技术命名；
- 活动名称「核心大使计划」。

历史任务卡 T043–T049 作为当时实现记录，不要求批量改写标题和历史证据。

## 3. 团队名模型

为 `AmbassadorTeam` 增加稳定团队名字段。

规则：

1. 后台可指定 / 修改团队名；
2. 未指定时系统自动生成**可读且在本期活动中可区分**的兜底名称；
3. 团队名属于团队本身，与该团队的**团队招募码**一一对应；
4. 不把团队名存进二维码 code 文本本身，二维码仍解析到 team；
5. 首版团队名只用于后台识别、周运营分析、导出等运营场景；
6. **App 暂不展示团队名**；
7. 旧 seed / 已有团队无 teamName 时必须兼容自动兜底，不能因 schema 升级失效。

建议兜底语义使用学校 / 校园大使可读信息 + 短序号，不向业务页面暴露 accountId 或长技术 ID。

## 4. 条款同步

现有已发布 V1.0 原型条款中涉及「核心大使 / 推广伙伴」的展示正文需要同步为最新身份名称。

技术 ID 可继续沿用，不要求因文案调整迁移历史引用。
