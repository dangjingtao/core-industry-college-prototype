## 1. 目标

为运营提供**按周查看团队拉新效果**的工作视角，并支持导出指定团队或全部团队数据。

本卡的“按周”是运营分析，不是财务周结算：不新增结算单、金额、对账、打款状态等财务模型。

## 2. 周度口径

首版按**自然周**聚合有效新增。

每周至少能回答：

- 本周各团队带来多少有效新增；
- 相比上一周是上升、持平还是下降；
- 某个团队本周由哪些成员贡献；
- 本周新增发生在什么日期 / 时间；
- 当前团队累计有效新增是多少。

统计事实继续以 `validAcquisitions.registeredAt` 为准，不复制第二份周统计真相源。

## 3. 活动 / 团队列表周视角

PC 核心大使计划工作台增加周维度切换 / 筛选。

列表至少支持：

- 选择当前周 / 前后周；
- 团队名；
- 校园大使；
- 学校；
- 团队状态；
- 团队人数；
- 本周有效新增；
- 累计有效新增；
- 相比上周的变化（允许首版用数量差 / 趋势标签，不强制复杂百分比）；
- 基础团队状态筛选。

首版不要求图表大盘堆叠，优先保证运营一眼能比较团队。

## 4. 团队周详情

团队详情增加明确的周度运营区。

至少展示：

- 当前所选自然周；
- 本周有效新增；
- 累计有效新增；
- 上周有效新增 / 周环比趋势；
- 按成员拆分的本周贡献；
- 本周拉新明细；
- 可切换其它周查看历史。

成员角色显示使用 V1.1 最新展示名：校园大使 / 校园推荐官。

## 5. 数据导出

支持两种导出范围：

1. **指定团队导出**：从团队详情或选中团队导出；
2. **全部团队导出**：按当前活动 + 当前所选周导出全部团队运营数据。

首版导出可以 CSV 为主，不要求 Excel 富格式。

导出至少包含：

- 活动；
- 周期起止日期；
- 团队名；
- 学校；
- 校园大使；
- 团队状态；
- 团队人数；
- 本周有效新增；
- 累计有效新增；
- 成员身份 / 成员标识；
- 成员本周有效新增；
- 必要拉新明细字段（新用户标识、注册时间、归因成员）。

如果“全部团队”导出同时包含汇总与成员明细，允许采用一行一成员 / 一行一拉新记录的扁平结构，需保证运营可用表格继续处理。

## 6. 与团队激励的关系

现有团队激励「未处理 / 已处理」继续保留，但**不与周度运营视角绑定成周结算状态**。

周度数据仅帮助运营观察效果和做线下业务判断。

## 7. 验收

- [ ] PC 可切换自然周查看团队运营数据；
- [ ] 团队列表展示本周有效新增和累计有效新增；
- [ ] 可识别相对上周趋势；
- [ ] 团队详情可看所选周的成员贡献和拉新明细；
- [ ] 周数据直接由有效新增事实按 `registeredAt` 派生，不建立第二份统计状态；
- [ ] 支持导出指定团队；
- [ ] 支持导出当前活动 / 当前周全部团队；
- [ ] 导出使用校园大使 / 校园推荐官最新展示名；
- [ ] 周运营不产生金额 / 对账 / 打款模型；
- [ ] PC typecheck / build / browser regression 通过。

## 8. 明确不做

- 不做财务周结算；
- 不做复杂 BI、自定义指标体系；
- 不做排行榜奖励规则；
- 不做跨活动长期经营报表；
- 不引入新的后端统计真相源。
