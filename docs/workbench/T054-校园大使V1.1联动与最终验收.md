# T054｜校园大使 V1.1：前后台联动与最终验收

## 1. 目标

在 T050–T053 完成后，对 V1.1 进行一次跨端收口，确认展示名、团队名、问卷答案、周度运营、导出和 App 经营视角使用同一业务事实，并完成最终回归。

本卡不再增加新功能。

## 2. 最终业务链

需要连续验证：

```text
PC 创建 / 编辑核心大使计划
→ 配置校园大使申请问卷
→ 学校招募码进入 App 校园大使申请
→ 提交问卷并形成团队
→ 后台看到团队名（指定或自动兜底）
→ 校园大使获得团队招募码
→ 校园推荐官加入
→ 1 校园大使 + 3 校园推荐官后自动点亮
→ 全员获得个人专属推广码
→ 新用户注册形成有效新增
→ App 校园大使「我的团队」直接看到本周经营概览
→ PC 按相同自然周看到团队本周数据
→ PC 团队详情查看完整申请问卷答案
→ PC 导出指定团队 / 全部团队数据
→ 校园推荐官始终看不到经营成果数字
→ 活动结束后历史保留、招募与推广失效
```

## 3. 展示语义总检查

所有当前产品页面必须使用：

- 校园大使；
- 校园推荐官。

同时确认：

- 活动名称「核心大使计划」未误改；
- 技术 role / 类型 / 路由不因展示名调整发生无价值迁移；
- 历史任务卡不作为当前产品文案验收范围。

## 4. 团队名联动

确认：

- 新团队创建后一定有可用 teamName；
- 后台修改团队名后列表、详情、导出一致；
- 未指定时自动兜底；
- 团队招募码仍解析到正确 team；
- App 不展示 teamName；
- 旧团队数据能正常兼容。

## 5. 问卷联动

确认：

- PC 配置的问卷结构被 App 正确渲染；
- App 提交答案后 PC 团队详情完整可读；
- 问题顺序、选项、答案不明显错配；
- 实际同意条款版本可追溯；
- 校园推荐官加入团队不被要求填写问卷。

## 6. 周度运营一致性

同一组选定数据在 PC / App 必须得到一致结果：

- 当前自然周有效新增；
- 上一周有效新增；
- 累计有效新增；
- 成员本周贡献；
- 拉新明细。

统计统一基于有效新增 `registeredAt` 派生。

不得出现 PC 一套周口径、App 另一套周口径。

## 7. 导出验收

至少验证：

- 指定团队导出；
- 当前活动 / 当前周全部团队导出；
- 导出字段与页面数据一致；
- 团队名、校园大使 / 校园推荐官展示名正确；
- 时间范围清晰；
- 导出不包含无关原型调试字段。

## 8. 权限回归

校园大使：

- 可查看团队经营成果；
- 可查看成员贡献与必要拉新明细。

校园推荐官：

- 不可查看本人新增数字；
- 不可查看团队总新增；
- 不可查看其他成员贡献；
- 不可查看经营看板 / 排行。

PC 运营端：

- 可查看问卷答案、团队与周度成果；
- 可导出运营数据。

## 9. 生命周期回归

保持 T049 已确认规则：

- 未开始活动二维码不可形成业务；
- 已结束活动学校码 / 团队码 / 推广码失效；
- 历史团队、问卷答案、推广成果保留；
- 旧团队不阻止下一期重新参加；
- 周度历史视角不会因为活动结束而丢失。
