原型中存在明显复制粘贴造成的 hotspot 错链。此类错误**不得原样复刻**。

判断规则：

```text
页面标题 / 所属技能
+ 页面内容
+ 标准母流程
> 单个明显错误 hotspot target
```

标准母流程为：

```text
技能入口
→ 动态答题
→ 生成确认（该技能存在时）
→ 任务进度
→ 成果详情
```

若遇到无法判断的跳转，不允许施工线程自行创造新业务流程，先记录证据与冲突。

## Mockplus 已明确的共用交互

以下属于原型事实，不是后续增强项：

- 工坊公共层包含：历史成果、项目详情、算力明细、技能矩阵；
- 技能任务以动态问答为主，明确出现单选 / 多选、AI 动态调整后续问题、作答完善度；
- 答题末尾可有补充说明与文件上传；原型列出 PDF、Excel、CSV、图片；
- 生成确认页显示：问答摘要、AI 提取核心信息、主观补充、作答完善度、预计算力消耗；
- 原型示例明确显示“当前可用 820、冻结 100、完成后按实际结算”；这些数字仅是 Mockplus 示例数据，不是经济规则；
- 团队型技能生成结果对全队可见，队员可编辑后提交确认，队长可采纳或标记用于比赛；
- S6 生成结果明确为**仅自己可见**；
- 任务进度页明确支持离开页面，完成后通过站内消息通知；
- 任务进度明确展示已冻结算力、已读取参赛档案、已检查问答材料、生成中、质量检查；
- 成果详情提供编辑 / 分享 / 提交确认等动作，具体内容结构按技能分别实现。

## 六阶段产品语义

拆卡不改变六阶段方向：

1. S1｜项目洞察

## 全局 Guardrails

三张子卡共同遵守：

- 创赛工坊必须依附具体 `competitionId` / 赛事 workspace，不做全局 AI 工具箱；
- 不新建第二份赛事身份、团队、项目档案真相源；复用 workspace 已有上下文；
- OPC 真实运行未接入前使用明确 mock，不伪造在线 AI 服务；
- 主交互遵循 Mockplus 的动态答题、结构化选择、补充、上传、生成确认、任务进度与成果页；
- 共用任务状态、历史成果、算力展示只建立一套；T013B / T013C 必须复用 T013A 底座；
- F04 Decision A 未最终确认前，算力 / 学力值只允许按 Mockplus 示例占位，不自行确定真实经济规则；
- AI 产出不得改写系统可信事实，不构造黑盒人才总分。
