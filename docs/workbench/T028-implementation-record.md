## 本轮已施工

### Mobile｜账号识别与认领状态

在现有登录 / 微信登录流程上补充三种中保真状态，不新增第二套 session / identities / Profile 真相源：

1. **历史账号命中**
   - 手机号验证后继续使用现有长期账号；
   - 不重复创建赛事账号。
2. **队长代录待认领账号**
   - 手机号验证后认领现有记录；
   - 不重新注册第二个账号。
3. **手机号账号冲突**
   - 明确停止自动合并；
   - 原型不执行资产迁移，等待产品确认人工核验与迁移规则。

同时：

- 微信登录可携带同一账号识别场景；
- 新用户微信登录 → 手机号 → 新账号 → onboarding 的既有流程保持不变；
- 邮箱仍只作为会议当前已知的赛事通知字段，不在本轮另建邮箱账号体系；
- 原型新增场景切换入口，便于产品 / 测试直接复核四种状态。

## 仍待确认的业务规则

### 会阻塞最终账号模型

1. **长期账号唯一身份锚点**
   - 手机号是否正式成为唯一锚点；
   - 或手机号只是主要验证凭证，内部仍以稳定 User ID 为真正账号主键。
2. **历史三创赛账号归并规则**
   - 命中后是直接认领、绑定、还是需要人工确认；
   - 多个历史账号命中同一手机号时如何处理。
3. **队长代录预账号定义**
   - 队长录入成员时到底创建“预账号”、只创建“待认领赛事成员记录”，还是其它对象；
   - 首次认领后需要补哪些资料。
4. **手机号冲突与资产迁移**
   - 冲突由谁审核；
   - 赛事身份、证书、课程、简历等长期资产是否允许迁移 / 合并。

### 不阻塞当前原型，可后补

5. **微信 OpenID / UnionID 与长期账号的正式绑定关系**；
6. **PC 登录方式**：手机号 + 密码、手机号 + 验证码，或历史赛事账号兼容入口；
7. **邮箱历史用途**：仅正式通知，还是允许做旧账号检索 / 找回；
8. **手机号换绑规则**：验证条件、频率限制、冷却期、历史手机号保留策略。
