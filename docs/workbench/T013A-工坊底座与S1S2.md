# T013A｜创赛工坊底座 + S1 项目洞察 + S2 项目诊断

**类型：施工卡**  
**状态：待执行**  
**优先级：P0**  
**前置：赛事工作区已有团队与项目上下文**

## 目标

先建立 T013 三张卡唯一共用的创赛工坊底座与标准任务闭环，再完成 S1 / S2。后续 T013B、T013C 必须复用本卡的 Runtime、历史成果、算力展示和页面 Pattern，不得另起一套。

## 一、工坊底座

### 最低交付

- [ ] 创赛工坊首页：展示 S1-S6 六阶段技能矩阵、当前阶段与推荐下一步。
- [ ] 技能包详情页：技能说明、适用阶段、参与角色、预计产出、所需算力占位、开始任务。
- [ ] 建立共用 Task Runtime 原型：至少表达草稿 / 待确认 / 运行中 / 已完成 / 失败或可重试等可解释状态。
- [ ] 任务进度页：运行中状态明确，可离开页面，再进入后能恢复同一任务状态。
- [ ] 共用成果详情 Pattern：报告分块展示，支持采用 / 暂不采用；后续版本能力由需要的技能包复用。
- [ ] 历史成果页：按当前赛事展示工坊历史产出，不跨赛事混杂。
- [ ] 算力明细页：余额、收支 / 消耗记录仅作原型占位；真实规则继续受 F04 Decision A 约束。
- [ ] 权限边界：队长确认启动的任务不能被普通成员伪装成已确认；成员参与采集时保留自己的作答归属。

### Runtime 边界

- 不新建第二份 `CompetitionIdentity`、Team、CompetitionProject 真相源。
- Runtime 只记录“这次技能任务”的输入快照、运行状态与产物引用。
- 任务完成后，真正被采用的结论 / 素材按所属领域回流；不能把整个 workspace 状态复制进 Runtime。
- OPC 未真实接入前必须明确使用 mock 运行与 mock 产物，不展示虚假的真实 AI 在线状态。

## 二、S1｜项目洞察包 · 找方向

### 采集

- [ ] 赛道倾向测试。
- [ ] 选品评分量表。
- [ ] 竞品点选对比。
- [ ] 目标用户多选。
- [ ] 全员可作答，队长查看汇总并确认生成。

### 产出与回流

- [ ] OPC 项目洞察报告：结论 / 依据 / 风险 / 推荐赛道。
- [ ] 手机端回流：赛道推荐卡 + 待验证清单。
- [ ] 报告中的推荐只作为工坊建议，不直接覆盖项目可信事实或官方赛道事实。

## 三、S2｜项目诊断包 · 做项目

### 采集

- [ ] 项目真实性自测。
- [ ] 证据上传 / 点选确认。
- [ ] 商业模式勾选。
- [ ] 成员分工测评。
- [ ] 队长触发诊断，成员可补充证据；生成前由队长确认。

### 产出与回流

- [ ] OPC 项目诊断报告：体检结论 / 缺口 / 行动清单。
- [ ] 手机端回流：风险缺口卡 + 优先行动列表。
- [ ] 证据上传使用中保真 mock 即可，不伪造文件解析或真实性鉴定。

## 标准验收动线

```text
赛事工作区
→ 创赛工坊
→ 六阶段矩阵
→ S1 或 S2 技能详情
→ 结构化采集
→ 队长生成确认
→ Runtime 运行中（可离开）
→ 回到工坊恢复任务
→ 成果详情
→ 采用结果
→ 历史成果可查
```

## 禁止

- 不把工坊入口搬成公共平台一级 AI 入口。
- 不用开放式聊天代替 S1 / S2 的结构化采集。
- 不把 AI 推荐赛道直接写成官方赛事事实。
- 不在本卡决定真实算力价格、学力值兑换关系。
- 不为 T013B / T013C 预建第二套 Runtime。
