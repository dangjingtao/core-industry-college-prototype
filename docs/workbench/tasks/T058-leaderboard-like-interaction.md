# T058｜排行榜点赞与周周期交互

**原派卡编号：T046（因与既有核心大使任务链编号冲突，2026-09-02 纠正为 T058）**  
**类型：原型设计 / 施工卡**  
**状态：PASS**  
**范围：V1.0 正常需求**  
**前置：T056 排行榜详情页**

## 背景

点赞属于学习排行榜 V1.0 的正式互动能力。点赞用于增强榜单互动感，但不改变学习排名。

## 目标

完成点赞、取消、重新点赞、自赞限制以及周榜周期的完整可演示交互。

## 产品规则

- 用户可以给排行榜中的其他用户点赞。
- 每名用户在同一个周榜周期内，对同一用户最多存在 1 个有效点赞状态。
- 第一次点击：点赞。
- 已点赞后再次点击：取消点赞。
- 取消后再次点击：重新点赞。
- 用户不能给自己点赞。
- 点赞数不影响排行榜排名。
- 点赞跟随周榜周期，新一周进入新的点赞周期。

## 原型实现点

- 本校榜与全国榜榜单项均使用真实可点击点赞按钮并展示本周点赞数。
- 未点赞态：空心 Heart + 当前本周点赞数。
- 已点赞态：使用现有 primary container / brand token 强调，并填充 Heart。
- 再次点击取消点赞，点赞数同步 -1；取消后可重新点赞。
- 用户本人行点赞按钮为 disabled，并通过 `aria-label` 明确“不能给自己点赞”。
- 点赞前后榜单排名、学习时长和列表顺序完全不变。
- 同一公开用户在本校榜 / 全国榜中复用同一 `personKey` 时，共享当前周的点赞状态。
- 当前用户在本校榜 Top 10 外「我的排名」与全国榜 Top 10 内使用同一基础点赞数，避免同一周数据自相矛盾。
- 当前查看者的有效点赞集合按周一起存入 prototype localStorage；storage key 使用当周周一日期，因此旧周状态不会污染新周。
- 页面规则文案明确“点赞按周记录；取消后可以重新点赞，新一周会进入新的点赞周期”。

## 最低可演示路径

```text
未点赞
→ 点击点赞
→ 已点赞 / 点赞数 +1
→ 再次点击
→ 取消点赞 / 点赞数恢复
→ 再次点击
→ 重新点赞
```

同时可验证：

```text
用户本人
→ 点赞入口 disabled
```

## UI 完成度要求

- 点赞按钮、数量、已点赞反馈均复用项目现有 design token 和 lucide icon 语言。
- 点击反馈清楚但克制，不做重社交动效。
- 状态变化在原型中真实触发，不依赖静态截图。
