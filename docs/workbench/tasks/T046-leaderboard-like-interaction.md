# T046｜排行榜点赞与周周期交互

**类型：原型设计卡**  
**状态：TODO**  
**范围：V1.0 正常需求**  
**前置：T044 排行榜详情页**

## 背景

点赞属于学习排行榜 V1.0 的正式互动能力。点赞用于增强榜单互动感，但不改变学习排名。

## 目标

完成点赞、取消、重新点赞、自赞限制以及周榜周期的完整可演示交互。

## 产品规则

- 用户可以给排行榜中的其他用户点赞。
- 每名用户在同一个周榜周期内，对同一用户最多存在 1 个有效点赞状态。
- 第一次点击：点赞。
- 已点赞后再次点击：取消点赞。
- 取消后再次点击：重新点赞。
- 用户不能给自己点赞。
- 点赞数不影响排行榜排名。
- 点赞跟随周榜周期，新一周进入新的点赞周期。

## 原型实现点

- 本校榜与全国榜榜单项均展示点赞入口与本周点赞数。
- 支持明确的未点赞态。
- 支持明确的已点赞态。
- 已点赞后再次点击可进入取消状态。
- 取消后可再次点赞。
- 用户本人行必须在 UI 上体现不可自赞状态，不能只依赖说明文字。
- 点赞前后排行榜名次保持不变。
- 本校榜、全国榜、Top 10 和「我的排名」中的点赞视觉规则保持一致。
- 页面需要让用户理解点赞为本周互动数据，不能让历史累计赞与周榜混淆。

## 最低可演示路径

```text
未点赞
→ 点击点赞
→ 已点赞 / 点赞数反馈
→ 再次点击
→ 取消点赞
→ 再次点击
→ 重新点赞
```

同时必须可验证：

```text
用户本人
→ 点赞入口不可用
```

## UI 完成度要求

- 点赞按钮、数量、已点赞反馈均复用项目现有 design token 和 icon 语言。
- 点击反馈清楚但克制，不做与学习榜定位不匹配的重社交动效。
- 状态变化必须能在原型中真实触发或通过项目 Prototype Runtime 明确切换，不只画静态截图。

## 验收

- [ ] 未点赞 → 点赞 → 取消 → 再点赞可完整演示。
- [ ] 点赞数量有同步视觉反馈。
- [ ] 用户本人不可点赞在 UI 上可验证。
- [ ] 点赞不会改变榜单排名。
- [ ] 本校榜 / 全国榜点赞规则一致。
- [ ] 周周期规则在页面或交互说明中明确。
- [ ] 新周点赞周期与历史累计数据不会在原型表达中混淆。
