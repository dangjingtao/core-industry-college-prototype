# T015｜登录注册流程

**类型：施工卡**  
**状态：待评审**
**优先级：P0**

## 背景

旧原型登录/注册流程包含邮箱登录、账号密码/验证码登录、信息填写、预备页/引导页。新原型当前直接进入已登录状态，缺少登录注册流程。

> 注意：F01 已建立 StudentProfile 学生主档，本卡在此基础上补充登录注册与 onboarding 引导。

## 目标

实现普通的登录注册流程，并在注册/登录后引导学生完善必要资料。

## 最低交付

- [x] 启动页 / 预备页：首次进入的功能介绍，并进入登录注册。
- [x] 登录页：手机号/邮箱 + 密码登录、验证码登录、忘记密码入口；微信登录进入独立授权页。
- [x] 注册页：手机号 + 验证码注册并自动登录，无需设置密码；用户协议/隐私政策在注册页声明。
- [x] 信息填写页：完善个人资料（昵称、学校、专业、城市、身份类型等），复用 F01 StudentProfile。
- [x] 登录状态管理：登录后进入首页，未登录时访问需要登录的页面引导登录。
- [x] 退出登录后回到登录页（F03 已处理退出逻辑，本卡确认登录页承接）。
- [x] 表单校验：手机号/邮箱格式、验证码占位、密码强度提示。

## 禁止

- 不引入真实后端鉴权；登录/验证码使用 mock，状态明确。
- 不把旧问卷 1:1 恢复；仍有业务价值的维度继续按 F01 决策归入同一 StudentProfile 与可跳过问卷。
- 不新建独立 profile 与 F01 StudentProfile 脱节。
- 不伪造真实短信/邮件验证码发送。

## 验收动线

```text
启动页（可跳过）
  → 登录页
  → 注册页 → 验证码 → 自动登录
  → 信息填写（复用 StudentProfile）
  → 首页

登录页 → 微信登录 → /auth/wechat/authorize（身份授权）
        → /auth/wechat/phone（获取绑定手机号）
        → 新用户：创建账号 → 信息填写；已有账号：直接登录回 returnTo

已登录 → 我的 → 退出登录 → 登录页
```

- F01｜学生主档 + Onboarding / Profile
- F03｜退出登录

- 登录支持手机号 / 邮箱与密码、原型验证码两种方式；注册仅接受手机号，验证码校验通过即自动登录，不再要求设置密码。
- 微信登录拆为独立两页：`/auth/wechat/authorize`（微信身份授权）→ `/auth/wechat/phone`（获取微信绑定手机号），不在登录页内完成绑定。新用户必须先取得绑定手机号才能建立长期账号；已有手机号直接登录并保持 `returnTo`；新手机号复用 `registerAccount()` 与 Long-term Assets 初始化逻辑创建账号，再进入 onboarding，不新增微信 Profile 真相源。
- 注册及找回密码统一使用明确展示的 mock 验证码 `123456`，不发送真实短信或邮件，也不接入后端鉴权。
- 注册创建新账号时复用 Public Platform 的唯一 `session / identities[] / applications / followedCompanies`，并初始化既有 Long-term Assets Store；不新增第二份 session、赛事身份或 Profile 真相源。
- 注册资料与 F01 的 `StudentProfile` 共用同一 Store；完成基础资料后进入可跳过问卷，再按安全的站内 `returnTo` 回到原操作。
- 未登录访问账号能力继续由 `AccountRequired` 引导登录；已登录但资料未完成时引导补充 onboarding；退出登录经二次确认后由 `/auth/login` 承接。
- 表单校验覆盖大陆手机号、基础邮箱格式、6 位原型验证码；登录密码强度、找回密码两次一致与协议勾选仅保留在对应路径。注册不设密码强度与协议勾选步骤。
