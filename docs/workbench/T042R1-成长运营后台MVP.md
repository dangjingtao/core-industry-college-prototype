## 1. 修补目标

作为 T042 的后续修订卡，在现有 `/admin/*` 控制面新增一级菜单 **「成长运营」**，补齐徽章体系在 PC 运营侧的可配置原型，用于承接：

- 徽章管理；
- 可信证书资格规则；
- 可信证书自动签发记录；
- 大礼包；
- 广告场景。

本卡只负责后台原型，不重做学生端 T038–T042，也不占用后续主任务编号。

## 3. 徽章管理

### 列表

展示：徽章名称 / 图形、品相 G1-G4、来源类型、获得条件摘要、已获得人数、状态、更新时间。

支持：搜索、筛选、新建、编辑、停用、查看获得记录。

### 新建 / 编辑

首期采用 **模板 + 参数**，不做万能规则编辑器。

支持模板：

1. 累计行为：行为类型 + 次数；
2. 连续行为：行为类型 + 连续天数；
3. 课程完成：指定课程；
4. 考核通过：指定小测 / 考核；
5. 赛事 / 进度事实：赛事 + 事实类型 + 目标状态。

首期只允许平台运营 / 超级管理员创建和编辑徽章。

---

## 4. 可信证书｜资格规则

MVP 固定结构：

```text
指定可信课程完成（必填，课程自带徽章）
+ G3 徽章 >= 2
+ G1 徽章 >= 5
+ 结业考试通过
→ 达到可信证书资格
```

页面字段：

- 证书名称；
- 指定可信课程；
- 课程完成徽章；
- G3 最低数量；
- G1 最低数量；
- 结业考试；
- 签发 Provider / 模板；
- 状态。

后台不得提供「无需可信课程即可拿证」的配置能力。

---

## 5. 可信证书｜自动签发记录

资格满足后直接调用外部 API，不做人工审批。

状态：

```text
pending → issuing → issued
                  ↘ failed → retry
```

列表展示：学生、证书、可信课程、资格达成时间、Provider、状态、尝试次数、最后错误、外部证书 ID、签发时间。

必须有稳定幂等键，避免重复签发和重复成本；失败重试复用原任务，不创建第二份签发事实。

---

## 6. 大礼包

学生满足徽章门槛后自动解锁领取资格，不做人工审核。

后台支持：

- 礼包名称与说明；
- 展示图；
- 有效时间；
- G1-G4 数量门槛；
- 指定必备徽章（可选）；
- 库存 / 限量（可选）；
- 领取后的权益承接方式；
- 状态。

成长运营只负责资格，实际领取 / 发放继续由权益领域承接。

---

## 7. 广告场景

首期固定承接：

- T038 福利领取激励广告；
- T038 权益详情信息流；
- T039 机会信息流；
- T040 App 冷启动开屏；
- T041 每日打卡。

配置字段：

```text
enabled
adType
triggerMode
skipPolicy
frequencyRule
businessAction
```

T041 额外可切：

```text
A 普通签到
B 广告作为签到条件
C 签到后广告作为额外奖励
```

不管理广告主、素材、竞价或投放算法。

---

## 8. UI / 交互要求

- 复用现有 PC 管理端设计语言；
- 以「列表 + 新建 / 编辑抽屉（或详情页）」为主；
- 不做节点编排器；
- 表单旁提供人类可读的规则摘要；
- 状态与异常必须可见；
- 已经发放给学生的徽章 / 证书历史不能因规则停用而消失。

---

## 9. 必须演示的两条链路

### A. 可信证书

```text
配置课程完成徽章
→ 配置：指定课程 + G3>=2 + G1>=5 + 结业考试
→ 学生满足条件
→ 自动生成签发记录
→ 模拟 API 成功
→ 学生获得可信证书
```

并至少演示一次：API 失败 → 后台失败状态 → 重试成功。

### B. 大礼包

```text
配置行为徽章
→ 配置礼包门槛
→ 学生通过签到 / 广告 / 活动获得徽章
→ 自动解锁礼包
→ 领取权益
```

---

## 10. MVP 不做

- 万能规则引擎 / 任意 AND OR 条件树；
- 学校 / 企业自行创建规则；
- 人工证书审批；
- 证书现金购买；
- 广告投放后台；
- 复杂积分商城；
- 独立 BI 大屏。
