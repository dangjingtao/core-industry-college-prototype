## 目标

完成 S5 / S6，并对 S1-S6 的入口、Runtime、角色、历史成果、算力占位和长期回流做一次总收口。T013C 不是重新设计工坊，而是把六阶段真正串成同一赛事上下文中的完整闭环。

## 一、S5｜赛事冲刺包 · 打比赛

### 采集

- [ ] 评分预检自评。
- [ ] 比赛材料勾选 / 完整度确认。
- [ ] 路演时长选择。
- [ ] 模拟问答结构化采集 / 演练入口。
- [ ] 队长触发，全员可参与演练；正式生成前由队长确认。

### 产出

- [ ] OPC 赋能成果报告：评分预检、PPT 结构、路演稿、问答建议。
- [ ] 手机端回流：评分预检卡 + 路演稿 / 问答卡。
- [ ] S5 涉及文案 / PPT 结构时复用成果版本能力：保存、对比、采用。
- [ ] “一键用于比赛”只表达采用到赛事工作材料，不伪造真实官方提交。

## 二、S6｜职业规划顾问 · 赛后规划

### 采集

- [ ] 自动带入当前成员可用的参赛表现 / 已有长期事实摘要，只读展示来源。
- [ ] 职业倾向测评。
- [ ] 能力自评量表。
- [ ] 发展方向点选。
- [ ] 每位成员独立完成，不由队长代替生成个人职业规划。

### 产出

- [ ] 核心产业学院职业规划报告：参赛画像、能力评估、差距分析、发展路径。
- [ ] 手机端回流：个人职业规划卡 + 课程 / 实训推荐入口。
- [ ] AI 规划只能作为建议层，不改写 StudentProfile、证书、成绩、赛事结果等可信事实。
- [ ] 不生成黑盒人才总分；推荐必须能说明来自哪些明确输入 / 经历。

## 三、六阶段总收口

### 一致性

- [ ] S1-S6 全部从同一个创赛工坊矩阵进入，技能详情 Pattern 一致。
- [ ] 六个技能包共用 T013A 的 Task Runtime，不存在第二套运行状态。
- [ ] 历史成果能按当前赛事查看，并明确技能包、发起人 / 参与者、状态、时间。
- [ ] S3 / S5 版本能力共用同一版本 Pattern。
- [ ] 算力余额 / 流水 / 消耗展示只有一套，F04 未确认前继续标记原型占位。
- [ ] 队长确认型任务与个人独立型任务权限表达清楚。
- [ ] 赛事结束 / workspace 能力关闭后，允许保留的成果继续以长期成果 / 经历展示方式存在；不得为了保留成果而让赛事 Runtime 永久可运行。

### 非 happy path

至少覆盖：

- [ ] 运行中离开再进入。
- [ ] mock 运行失败 → 重试。
- [ ] 非队长尝试启动队长确认型任务。
- [ ] 缺少必要采集项时阻止生成。
- [ ] 当前赛事 ended / revoked 时禁止新开赛事期技能任务，并保留已完成成果的可查看性。
- [ ] 不同赛事之间历史成果、任务状态不串线。

## 禁止

- 不在收口阶段把六阶段重新合成一个巨型页面。
- 不为了“智能”增加全局开放式聊天入口。
- 不把 S6 职业建议变成人才评分或可信能力事实。
- 不伪造真实比赛提交、真实 AI 异步服务、真实算力扣费。
- 不因为赛事结束而删除已经形成的可保留成果，也不让 ended / revoked 赛事继续启动新 Runtime。
