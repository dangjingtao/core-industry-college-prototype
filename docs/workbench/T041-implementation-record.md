## 入口方案（当前实现）

采用 **方案 B：任务中心（`/tasks`）顶部常驻「每日打卡」签到条** 作为 MVP；首页 / 应用中心入口作为后续可扩展项，本次暂不施工。

理由：

- 任务中心语义与「任务/打卡」最匹配；
- 新手任务「每日打卡」项可直接跳转到 `/tasks`，完成打卡后自动回流完成状态；
- 不增加首页复杂度，避免与新手任务、赛事进度等入口争夺首屏空间。

## 关键实现

### 任务中心签到条

- `useCheckIn`：读取 / 写入 `localStorage` key `task-center-checkin`，保存 `{ date, streak }`；
  - 今日已打卡 → 显示已打卡状态；
  - 昨日已打卡今日未打 → 保留连续天数；
  - 断签一天以上 → 连续天数清零。
- `CheckInBar`：
  - 展示今日打卡状态、连续天数、打卡按钮；
  - 点击「打卡」进入 5 秒激励视频广告全屏层（`CheckInAdDialog`）；
  - 广告层带「广告」标识、倒计时、进度条与「放弃奖励」按钮；
  - 5 秒结束后自动关闭广告，标记已打卡，弹出「打卡成功，恭喜你获得 20 学力值（暂定）」；
  - 已打卡按钮支持再次点击重置为未打卡，方便原型演示。

### 新手任务联动

- 「每日打卡」任务 `to` 从 `/home` 改为 `/tasks`；
- `useTodayCheckIn` 读取同一 `task-center-checkin` key，保证任务中心打卡后新手任务自动完成；
- 移除新手任务内本地打卡动作，统一在任务中心完成，避免状态分叉。

## 约束落实

- 每日打卡状态独立于新手任务状态，新手任务全部完成后仍可打卡；
- 未新建第二份 session / identities / 学力值真相源；
- 学力值奖励数值与发放规则明确标记为「暂定」，等待 F04 经济模型决策；
- 原型阶段使用 `localStorage` 模拟，已预留后端接口替换点。
