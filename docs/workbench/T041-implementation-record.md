## 1. 原型落地目标

每日打卡从新手任务中解耦，成为长期存在的 App 行为。

当前继续采用：**任务中心 `/tasks` 顶部常驻每日打卡条** 作为 MVP 入口。

新手任务只负责引导用户来到打卡入口，不持有另一份打卡状态；新手任务全部完成后，每日打卡仍继续存在。

## 2. 统一打卡事实

- 打卡事实只保留一份；
- 任务中心、新手任务、徽章规则都读取同一事实；
- 当前原型用 `localStorage` key `task-center-checkin` 模拟；
- 后续真实实现替换为服务端事实时，不改变上述单一真相源原则。

## 3. 广告与打卡关系：改为可配置

2026-08-26 产品评审确认：广告与打卡不永久硬绑定。

原型基座应支持三种场景：

```text
A. 普通签到
   点击签到 → 签到成功

B. 广告作为签到条件
   点击签到 → 激励广告 → 完成广告 → 签到成功
   跳过广告 → 本次签到未完成

C. 广告作为额外奖励
   点击签到 → 签到成功
   → 可选择观看激励广告 → 获得额外奖励 / 徽章进度
```

具体阶段采用哪种策略，由薄运营配置决定。

## 4. 对当前中保真实现的修订要求

当前原型实现为“点击打卡 → 强制 5 秒广告 → 看完后才打卡成功”，只对应上述 **B 模式**，不能继续作为唯一业务规则。

需要修订：

- 抽出打卡基础动作，不让广告组件永久控制打卡事实；
- 增加场景策略开关，至少在原型数据层可切 A / B / C；
- B 模式下，跳过广告应表达为“放弃本次签到 / 条件未完成”，不能写“放弃奖励”却同时取消签到；
- C 模式下，必须先记录签到成功，再独立处理广告额外奖励；
- “20 学力值”继续保持暂定，不在本卡写死真实经济规则。

## 5. 新手任务联动

当前已完成的正确部分继续保留：

- 新手任务「每日打卡」跳转 `/tasks`；
- `useTodayCheckIn` 与任务中心读取同一打卡事实；
- 不在新手任务内再造本地打卡动作。

## 6. 连续打卡

当前原型已展示连续天数。以下内容仍不在本轮锁死：

- 连续奖励；
- 断签处理；
- 补签；
- 未登录用户；
- 提醒策略。

这些可以后续单独配置，不阻塞当前“长期打卡 + 广告可配置”主结构。
