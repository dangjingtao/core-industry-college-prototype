# T042｜徽章系统设计与原型落地方案

> 类型：产品决策 / 设计 / 原型施工输入
> 状态：产品骨架已确认，品相命名与具体数值待后续收口
> 初稿日期：2026-08-25
> 产品评审更新：2026-08-26
> 前置：F04 Decision A（学力值经济）、D03（任务体系）、T011 / T024（课程体系）、T034（课程考试 / 发证公信力）、T008（可信空间）、T017（长期简历 / 成长档案）
> 产品真相源：`docs/product/19-badge-ad-and-trusted-credential-prd.md`

> 历史说明：2026-08-25 脑暴稿提出“低级徽章 + 高级徽章 + 必修课程 = 更高级可信凭证”的方向。本版保留该组合思路，但按 2026-08-26 产品评审修正语义：**徽章品相只代表获取难度，不代表可信程度；可信证书不是最高级徽章，可信课程始终是证书硬门槛。**

---

## 1. 产品目标

平台需要一个能长期积累、可展示、又有实际用途的学生成就系统。

徽章不强制绑定课程，来源可以包括：

- App 行为；
- 日常任务；
- 课程学习；
- 小测 / 考核；
- 赛事身份；
- 赛事 / 项目进度；
- 运营活动；
- 未来其它可验证事实。

徽章至少有两条实际价值出口：

```text
路径 A：徽章 + 可信课程 + 考核 → 可信证书资格
路径 B：徽章 → 运营大礼包 / 礼券 / 福利资格
```

这样既服务愿意学习、拿证的学生，也服务不以课程和证书为目标但持续参与 App 的学生。

---

## 2. 核心模型：来源与品相拆开

徽章必须至少有两个独立维度。

```text
Badge
├─ sourceType：为什么获得
│  ├─ app_behavior
│  ├─ learning
│  ├─ assessment
│  ├─ competition
│  ├─ progress
│  └─ operation
│
└─ grade：获得有多难
   ├─ G1
   ├─ G2
   ├─ G3
   └─ G4 ...
```

### 2.1 来源类型

来源类型描述事实性质，不描述高低。

例如：

- 连续签到：App 行为；
- 完成激励广告任务：App 行为 / 运营行为；
- 完成课程章节：学习；
- 通过关卡小测：考核；
- 获得赛事身份 / 完成赛事节点：赛事 / 进度。

### 2.2 品相

品相只描述：

- 获取难度；
- 所需投入；
- 稀缺程度。

当前内部先使用 `G1 / G2 / G3 / G4` 占位。最终可以再设计为颜色、字母或其它视觉体系。

**品相不代表：**

- 官方可信度；
- 学术等级；
- 学生能力评级；
- 证书等级。

高品相徽章也不强制来自课程。完成可信课程并得到高品相学习徽章是最理想的一条路径，但高难赛事成果、长周期项目等未来也可以产生高品相徽章。

---

## 3. 可信证书关系

可信证书是独立的可信资产，不属于徽章品相中的“最高一档”。

平台已有外部权威可信认证签发渠道，单份签发存在真实成本，当前业务口径约 10 元 / 份；未来可信证书可进入学生简历。因此不能设计成普通付费商品，也不能让学生用现金绕过学习要求购买证书。

统一资格结构：

```text
指定可信课程完成
+ X 个高品相徽章
+ Y 个低品相徽章
+ 必要的小测 / 结业考核
→ 满足可信证书资格
→ 进入真实签发 / 领取流程
```

关键边界：

- 低品相行为徽章可以是证书必选条件；
- 这些徽章表达培养过程中的参与、投入和行为完成度，不等于专业能力证明；
- 无论积累多少徽章，都不能绕过可信课程直接拿证；
- 看广告不能直接被表达成“换证”或“解锁教育认证”。

---

## 4. 广告行为与徽章

激励广告可以作为某些行为徽章的获得条件之一。

推荐心智：

```text
完成激励广告行为
→ 完成某项 App / 运营任务
→ 推进或获得对应徽章
→ 徽章参与礼包或培养方案条件
```

前台不得出现：

```text
看广告 → 直接拿可信证书
看广告 → 购买可信认证
```

广告只是行为交换方式之一。

---

## 5. 微专业与小测

原则上学校 / 合作方的微专业课程托管于 App，课程进度、完成、小测与结业考核以课程事实源为准。

### 5.1 关卡小测

- 固定学习节点出现；
- 可作为某枚学习 / 考核类徽章的前置条件；
- 小测通过后推进或获得对应徽章；
- 具体题量、及格线、重试次数后续配置。

### 5.2 结业考核

- 课程 / 微专业完成后进行；
- 与可信课程完成事实、规定徽章组合共同决定可信证书资格；
- 具体考试规则后续收口。

徽章、小测和证书都引用课程真实记录，不各造第二份课程状态。

---

## 6. 新手任务落地

新手引导可以把“获得第一枚较高品相徽章”设计成重要目标，让用户尽早理解成就体系。

但不要求所有新用户强制完成高难课程。

原型应提供一条真实可达成路径，例如：

```text
新手任务
→ 查看徽章目标
→ 完成一组真实行为 / 学习任务
→ 获得第一枚较高品相徽章
→ 引导进入徽章墙查看下一目标
```

具体首枚徽章选哪一枚，在首批徽章清单确定时再收口。

---

## 7. 学生 App 原型结构

### 7.1 我的 → 徽章墙

至少展示：

- 已获得徽章；
- 未获得 / 进行中徽章；
- 品相；
- 来源类型；
- 获得时间；
- 达成条件与当前进度；
- 徽章可用于哪些目标（证书条件 / 礼包条件 / 单纯成就）。

徽章墙不能把“可信证书”作为一个更高品相徽章混排；可信证书应作为独立可信资产入口或关联目标展示。

### 7.2 场景联动

以下页面可以显示关联徽章：

- 任务中心 / 每日打卡；
- 课程详情 / 学习进度；
- 小测 / 考核结果；
- 赛事详情 / 赛事工作区；
- 活动 / 福利页面。

页面只显示关联规则与进度，最终发放事实统一由徽章规则基座生成。

### 7.3 获得反馈

获得徽章时提供轻量反馈：

- 徽章图形；
- 名称；
- 品相；
- 来源；
- 可去徽章墙查看。

不做重度游戏动画作为首期硬要求。

---

## 8. 大礼包：第二价值出口

并非所有学生都愿意通过 App 学习可信课程或拿可信证书。

运营可以配置：

```text
指定徽章组合 / 数量
→ 达成礼包门槛
→ 领取大额优惠 / 礼券 / 福利
```

研发提供基座，运营负责实际礼包内容与门槛。

首期原型至少需要：

- 礼包名称 / 说明；
- 有效期；
- 徽章门槛；
- 库存 / 是否领完；
- 领取状态；
- 权益承接方式。

不在 T042 建复杂积分商城。

---

## 9. PC 运营端最小基座

首期不做大型运营系统，只需要薄配置能力。

### 9.1 徽章定义

- 名称；
- 图形 / 素材；
- 来源类型；
- 品相；
- 达成条件；
- 启停；
- 发放时间范围（如需要）。

### 9.2 可信证书资格规则

统一结构下配置：

- 指定可信课程；
- 指定徽章 / 数量组合；
- 关卡小测；
- 结业考核；
- 证书展示信息。

不得配置“无需可信课程即可拿证”的例外。

### 9.3 礼包规则

- 礼包内容；
- 徽章门槛；
- 时间；
- 库存；
- 状态。

---

## 10. 长期资产与事实源

徽章一旦合法获得，长期保留。

课程下架、赛事结束、活动结束后：

- 已获得徽章不删除；
- 来源停止继续发放即可；
- 保留来源与获得时间；
- 后续仍可作为历史成就展示。

徽章记录只保存必要引用，例如：

```text
badgeId
userId
ruleId
sourceType
sourceId
grade
grantedAt
```

课程、赛事、任务、广告、权益、证书各自维护真实事实，徽章系统只消费这些事实做规则判断。

## 11. 原型施工验收

### M1｜模型与徽章墙

- [ ] `sourceType` 与 `grade` 两维模型分离
- [ ] G1–G4 作为内部占位，可替换视觉命名
- [ ] 我的 → 徽章墙可展示获得 / 未获得 / 进度 / 来源 / 品相
- [ ] 徽章获得后长期保留

### M2｜行为与学习联动

- [ ] 每日打卡可推进徽章规则
- [ ] 激励广告完成事件可推进指定行为徽章
- [ ] 课程 / 小测事实可推进学习或考核徽章
- [ ] 赛事身份 / 进度可作为徽章来源

### M3｜可信证书资格

- [ ] 可信课程为不可绕过硬门槛
- [ ] 支持高 / 低品相徽章组合条件
- [ ] 支持小测 / 结业考核条件
- [ ] 徽章不足或课程未完成时明确展示缺少条件
- [ ] 达成后进入真实证书签发 / 领取流程，不把证书当徽章发放

### M4｜礼包出口

- [ ] 运营可配置礼包与徽章门槛
- [ ] 学生可看到还差哪些徽章
- [ ] 达成后进入真实权益领取流程

## 12. 仍待产品收口

以下不阻塞当前原型骨架：

1. 品相最终命名与层级数量；
2. 首批正式徽章清单；
3. 可信证书规则中的 X / Y 数量；
4. 小测 / 结业考核的题量、及格线与重试规则；
5. 首批可信课程范围；
6. 证书对外正式签发主体与认证名称口径；
7. 首批运营礼包内容、门槛与履约；
8. 哪些普通徽章允许进入可信空间 / 简历以及隐私规则。
