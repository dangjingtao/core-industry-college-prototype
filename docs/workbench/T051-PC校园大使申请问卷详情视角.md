## 1. 目标

沿用现有校园大使申请问卷配置能力，补齐后台的**完整问卷答案查看视角**，让运营可以从团队详情明确看到该团队校园大使提交的申请内容，而不是把几项答案散落成弱信息块。

本卡不新增第二份成员问卷；校园推荐官加入团队时仍不填写申请问卷。

## 2. 现有基础

现有能力继续复用：

- PC 活动创建 / 编辑中的轻量问卷设计器；
- 单行文本、长文本、单选、多选、必填配置；
- App 按活动配置动态渲染申请问卷；
- 申请记录保存实际问卷答案和条款版本；
- PC 团队详情已有基础申请信息读取能力。

本卡重点是把“能读到答案”提升为“运营能完整查看和理解答案”。

## 3. 团队问卷答案视角

在 PC 团队详情中增加明确的「校园大使申请问卷」区域 / 详情视角。

至少展示：

- 问卷名称 / 所属活动；
- 校园大使可读身份信息；
- 提交时间（若当前模型缺少稳定提交时间，可复用申请 / 入队时间作为原型事实并在实现记录注明）；
- 实际同意的活动条款版本；
- 按问卷字段配置顺序展示全部问题与答案；
- 长文本完整可读；
- 单选 / 多选按用户实际选项展示；
- 未填写的非必填项明确显示“未填写”，不隐藏字段。

## 4. 配置侧补强

现有问卷设计器继续保留，不建设通用问卷 SaaS。

需要检查并补齐：

- 字段顺序在保存、App 渲染和后台答案展示中保持一致；
- 单选 / 多选选项在答案视角中可读；
- 编辑活动后不应破坏既有申请记录的历史答案可读性；
- 已提交申请应按提交时字段语义尽量可追溯，不因后续表单配置变化出现明显错位。

中保真阶段如未建设表单 schema snapshot，至少要明确兼容策略和演示边界，不得把历史答案直接错配到新字段。

## 5. 团队详情信息层级

建议团队详情按运营心智分区：

```text
团队概览
→ 校园大使申请问卷
→ 成员
→ 拉新 / 运营成果
→ 团队激励
```

问卷答案不与成员拉新结果混在同一个数据块里。

## 6. 权限与边界

- 问卷答案属于后台运营视角；
- App 校园推荐官不可查看；
- App 校园大使不因本卡新增“查看自己申请问卷”的入口；
- 不新增人工审核状态；
- 不改变“提交后直接成为校园大使 · 待点亮”的既有规则。

## 9. 2026-08-27 Mira 独立复审

### 原结论：CHANGES REQUIRED

#### P1｜legacy 表单活动的新申请没有形成提交时 schema snapshot

原提交逻辑只在 `campaign.applicationForm` 存在时复制 `applicationFormSnapshot`。但共享模型仍正式支持仅含 `applicationFields` 的 legacy campaign，并通过 `ambassadorApplicationForm(campaign)` 兼容渲染。

因此：若一个 legacy campaign 在 T051 上线后继续接收新校园大使申请，该成员仍会得到 `applicationFormSnapshot = undefined`。后续运营编辑活动问卷时，历史答案只能回退读取“当前表单”，仍可能发生字段语义漂移。这与本卡“提交时字段语义可追溯 / 后续表单配置变化不明显错配”的验收合同不一致。

复审建议：申请提交时不要直接 snapshot `campaign.applicationForm`，而应 snapshot `ambassadorApplicationForm(campaign)` 的 resolved schema，并深拷贝 options。这样结构化表单与 legacy 表单走同一历史快照合同。

#### P2｜T051 缺少 focused browser regression

原 T051 实现提交对应的 Prototype Quality Gate 确实全绿，但当时 `apps/pc/tests/` 只有 T046 / T047 / T050 等大使专项测试，没有 T051 专项用例。原 PC regression 没有断言以下关键合同：

- 提交时 schema snapshot 优先于后续活动表单；
- legacy 无 snapshot 时的明确降级提示；
- 字段顺序、未填写、多选 / 长文本展示；
- 实际同意条款版本。

### 原复审通过条件

1. 修复 legacy `applicationFields` campaign 新提交的 schema snapshot；
2. 增加 T051 focused browser regression；
3. 重新运行 PC typecheck / build / browser regression，相关门禁全绿；
4. 再由独立复审确认后改为 PASS。

## 10. 2026-08-27 修复响应

### P1 修复

- `applyAsCoreAmbassador()` 不再直接读取可选的 `campaign.applicationForm`；
- 改为调用 `ambassadorApplicationForm(campaign)` 获取 resolved schema 后统一生成 `applicationFormSnapshot`；
- 因此结构化 `applicationForm` 与 legacy `applicationFields` 的新提交现在走同一 snapshot 合同；
- snapshot 中 choice `options` 继续深拷贝；
- `cloneState()` 同步深拷贝成员的 `applicationFormSnapshot` 及其 options，保持“提交时 schema 是冻结历史事实”的语义。

### P2 修复

- 新增 Mobile focused regression，直接验证 legacy 活动提交后的 persisted snapshot 为 `legacy-0 / legacy-1` resolved schema；
- 新增 PC focused regression：先写入提交时 snapshot，再故意替换当前 campaign form，确认 PC 仍显示旧问题 / 旧答案；
- PC focused regression 同时覆盖四种字段、字段顺序、未填写、提交时间、实际条款版本；
- 另增无 snapshot 的 legacy record 场景，要求 UI 明确显示“使用当前表单配置”及字段漂移 warning；
- focused tests 已接入现有 Quality Gate，不建立旁路验收脚本。
