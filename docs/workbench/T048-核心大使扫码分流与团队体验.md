# T048｜App：扫码分流、核心大使身份与团队招募体验

> 类型：产品收口 / 施工  
> 状态：待评审  
> 日期：2026-08-26  
> 前置：T043、T044、T045、T047  
> 来源：`docs/product/18-campus-ambassador-prd.md` + 2026-08-26 人工预演

---

## 1. 目标

把当前“已有路由但用户要理解编码”的原型，收口成真实用户能自然完成的扫码体验。

核心原则：核心大使计划不是 App 显性常驻入口，而是由「我的」页通用扫码器触发；扫码器识别不同码型后直接进入不同业务，不让用户自己判断码的用途。

## 2. 扫码总路由

通用扫码入口至少识别三类码：

```text
学校招募码
→ 核心大使申请

团队招募码
→ 推广伙伴加入确认

专属推广码
→ 新用户推广 / 注册落地
```

- 正常流程不展示原始 code 输入框；
- 学校招募码不得进入团队加入页；
- 团队招募码不得进入大使申请页；
- 码型错误 / 过期需给明确反馈，不出现“进入错误页面后才提示无效”的体验。

## 3. 学校招募码 → 核心大使申请

- 扫学校码后直接进入对应活动 / 学校的大使申请页；
- 页面明确说明申请的是「核心大使」，不是加入别人团队；
- 申请表按 T047 配置动态渲染；
- 「核心大使计划条款」标题可点击查看正式正文；
- App 不展示技术版本号；
- 用户同意并提交后进入「核心大使 · 待点亮」。

## 4. 申请成功后的长期入口

核心大使申请成功后，即使团队尚未点亮：

### 我的资料卡

- 姓名附近增加「核心大使」身份小标识；
- 待点亮阶段使用灰色 / 弱化状态；
- 点亮后的最终色彩和状态样式应与现有身份体系协调，不另造夸张视觉。

### 我的 → 服务入口

- 增加「我的团队」入口；
- 仅已进入核心大使团队体系的账号展示；
- 点击直达本人所属推广团队；
- 不要求「核心大使计划」作为 App 首页 / 应用中心显性功能出现。

## 5. 团队招募码展示

核心大使团队页：

- 团队招募码以真实二维码为主形态；
- 可保留短文本 / 复制作为辅助；
- 点击二维码打开移动端规范的 Modal / 大图预览；
- 支持长按保存或下载；
- 文案明确“仅用于邀请推广伙伴，不是学校招募码”；
- payload 必须进入团队邀请确认链路。

## 6. 团队招募码 → 推广伙伴加入

推广伙伴扫码后不再显示「输入团队招募码」页面。

正常页面应类似：

```text
XXX 邀请你加入推广团队
所属活动：……
所属学校：……
加入后身份：推广伙伴
活动期间不可退出或换队

[确认加入] [取消]
```

要求：

- XXX 优先展示核心大使昵称 / 姓名，不展示 accountId 技术值；
- 用户无需看到原始团队 code；
- 确认加入后进入本人的团队视角；
- 推广伙伴仍不得看到成果数字、团队成员明细或排名；
- 已点亮团队后加入的伙伴立即获得本人专属推广码。

## 7. 原型人工验收条件

当前单一账号会话不足以人工验证“大使 + 3 位推广伙伴”。本卡需为中保真原型提供最小、非生产的多用户模拟能力：

- 可以切换 / 指定测试账号，或提供等价演示入口；
- 能连续模拟至少 1 位大使 + 4 位推广伙伴；
- 测试能力不得伪装成正式用户功能；
- 正常业务页面不得暴露调试账号 ID / 长码作为用户操作要求。

## 8. 验收

- [ ] 通用扫码器可正确识别学校码 / 团队码 / 专属推广码；
- [ ] 学校码直接进入大使申请；
- [ ] 团队码直接进入邀请确认，不要求手输编码；
- [ ] 申请条款可点击阅读；
- [ ] 申请成功后「我的」出现灰色核心大使身份标识和「我的团队」入口；
- [ ] 团队招募码为真实可预览 / 保存二维码；
- [ ] 伙伴加入确认展示大使可读姓名，不暴露 accountId；
- [ ] 原型可人工模拟至少 1 大使 + 4 伙伴；
- [ ] Mobile route audit / typecheck / build 与必要 Playwright 通过。
