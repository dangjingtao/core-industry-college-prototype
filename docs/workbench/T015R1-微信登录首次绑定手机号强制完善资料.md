# T015R1｜微信登录首次绑定手机号强制完善资料

**类型：施工卡（T015 方向修订）**  
**状态：已完成**  
**优先级：P0**

## 当前原型完成度

- [x] `/auth/wechat/authorize` 授权页已存在，说明微信身份用途并引导下一步。
- [x] `/auth/wechat/phone` 绑定手机号页已存在：
  - 老用户（`wechatAccount=existing`）直接登录并返回 `returnTo`；
  - 新用户创建账号后通过 `navigate(/onboarding/profile?returnTo=...)` 强制进入资料完善页；
  - 未提供「跳过」或「直接进入首页」的入口。
- [x] 资料完善页复用 F01 `StudentProfile`，与手机号注册新用户共用同一 Profile 写入路径。
- [x] 登录状态仍由 `usePublicPlatform` / `useLongTermAssets` 维护，无第二真相源。

## 背景

T015 已实现登录注册流程，微信登录拆为 `/auth/wechat/authorize`（授权） → `/auth/wechat/phone`（获取绑定手机号）两页，新用户需先取得绑定手机号再创建账号。

昨天下班前内部会议进一步明确：

> 登录方式支持手机号、邮箱及微信，其中微信首次登录需强制绑定手机号并跳转至完善资料页。

本卡确保微信新用户绑定手机号后，必须完成资料完善页才能进入首页或 returnTo，而不是仅创建账号后直接登录。

## 目标

强化微信首次登录流程：授权 → 绑定手机号 → 强制完善资料 → 进入目标页。

## 最低交付

- [x] 微信授权页 `/auth/wechat/authorize`：明确告知用户将使用微信身份登录/关联，继续后进入手机号绑定页。
- [x] 手机号绑定页 `/auth/wechat/phone`：
  - 新用户必须输入手机号并验证（原型验证码占位）才能完成绑定；
  - 已绑定手机号的微信老用户直接登录并返回 `returnTo`；
  - 未绑定手机号不允许跳过或直接进入首页。
- [x] 绑定成功后，新用户强制进入资料完善流程：
  - 复用 F01 `StudentProfile` 资料填写页；
  - 完成后进入 `returnTo` 或首页；
  - 不创建独立的微信 Profile 真相源。
- [x] 资料完善页对微信新用户与手机号注册新用户保持一致体验，均写入同一 `StudentProfile`。
- [x] 登录状态管理、session / identities[] 等继续使用 Public Platform 与 Long-term Assets 既有 Store，不新增第二真相源。
- [x] 通过 mobile `typecheck` / `build`。

## 禁止

- 不引入真实后端鉴权；验证码继续使用 mock。
- 不新建独立微信 Profile 与学生主档脱节。
- 不允许微信新用户绕过手机号绑定或资料完善。

## 验收动线

```text
登录页 → 微信登录
  → /auth/wechat/authorize 授权
  → /auth/wechat/phone 绑定手机号
    → 老用户（已绑定手机号）→ 直接登录 → returnTo
    → 新用户 → 验证手机号 → 创建账号 → 强制进入资料完善
      → 完成 StudentProfile → returnTo / 首页
```
