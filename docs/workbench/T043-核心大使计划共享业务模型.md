## 1. 目标

先建立 App 与 PC 运营端共用的核心大使计划业务模型，保证活动、团队、成员、点亮状态和推广成果只有一套业务真相源。

## 2. 施工范围

首版至少覆盖：

- 一期核心大使计划 Campaign；
- 活动覆盖学校及学校大使招募码；
- 核心大使团队；
- 核心大使 / 推广伙伴的活动成员关系；
- 团队招募码、个人专属推广来源；
- 有效新增记录；
- 简单团队激励处理状态。

固定规则：

1. 每个团队仅 1 位核心大使；
2. 同一期活动，一个用户只能属于一个推广团队；
3. 核心大使 + 至少 3 位推广伙伴，总人数达到 4 人后自动点亮；
4. 4 人只是门槛，不是团队人数上限；
5. 活动期间不可退队、不可换队；
6. 活动结束后团队关系结束，二维码失效，历史记录保留；
7. 核心大使计划属于运营活动，不复制赛事身份模型。

## 3. 不做

- 不做永久大使等级；
- 不做多级代理 / 子团队；
- 不做真实财务分账；
- 不在本卡锁定真实安装归因服务。

## 4. 验收

- [ ] App 与 PC 可读取同一套活动 / 团队 / 推广成果状态；
- [ ] 达到 4 人时团队自动点亮；
- [ ] 点亮后继续加人不受 4 人限制；
- [ ] 活动结束后二维码和团队关系失效，历史仍可读；
- [ ] 未引入第二套 session / user / school / competition identity 真相源。
