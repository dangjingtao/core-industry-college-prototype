## 本轮修正

### 1. 业绩报告

旧原型把“团队业绩报告”做成了：

```text
填写阶段业绩摘要
→ 上传报告 / 数据附件
→ 提交
```

这与会议结论相反。

现改为：

```text
阶段结果发布
→ 报告可领取
→ 领取
→ 下载 / 进入长期资产
```

并在页面明确：**这里不是学生数据上传入口。**

原型用校赛 / 省赛 / 国赛三个阶段表达：

- 校赛：可领取（示例）；
- 省赛：待生成；
- 国赛：未开放。

这些是用于展示状态差异的原型示例，不代表真实赛事当前阶段配置。

### 2. 晋级结果

晋级结果单独成块，不和业绩报告合并。

原型示例采用：

```text
校赛报告：可领取
晋级结果：待公布
```

用于明确表达：**报告可领取不等于已经晋级。**

### 3. 普通电子证书

保留按赛事阶段下载的产品心智。

示例：

- 校赛普通电子证书：可下载；
- 后续阶段：未签发。

同时明确：证书签发不由“晋级”或“报告已生成”自动推导。

### 4. 官方可信证书

可信证书与普通电子证书分层展示。

当前原型阶段不满足高阶段资格，因此：

- 只说明可信证书的资格边界；
- 不展示假的“立即领取可信证书”按钮；
- 不模拟签发后台、API 或完整证书状态机。

## 明确不做

本卡不继续设计：

- 各赛事真实报告生成时间；
- 各阶段真实发证范围；
- 可信证书签发后台；
- 证书撤销 / 重签；
- 真实 PDF 下载；
- 晋级名单管理。

这些不是当前原型评审所必需。

## 当前结论

T031 已能回答原型评审需要的核心问题：

1. 学生在哪里领取业绩报告；
2. 阶段未到时看到什么；
3. 报告与晋级如何区分；
4. 普通证书与可信证书如何区分；
5. 为什么当前用户看不到可信证书领取入口。
